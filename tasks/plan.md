## 1. 审查结论

建议保留 NAS 影视自动化主链路，先修复数据一致性与误清理问题，再减少重复业务逻辑、配置入口和前端耦合。现有 FastAPI + SQLite + APScheduler + 原生 JavaScript 组合可以继续使用，无需先迁移框架。

## 2. 已验证的问题

以下相对路径与行号均以本次基线为准。复现使用临时目录、独立 SQLite 与假网盘/假下载器，没有调用真实网盘或真实下载器。

### F1 · P1 · 指定目录同步会清理同一网盘的其他目录

- 位置：`app/services/strm_sync.py:415`、`:422`，调用点约 `:335`。
- `_clean_invalid` 只按 `site_id` 选取整个盘的记录，没有限定本次 `pan_path` 或同步目标范围。
- 复现：已有 `/B/old.mkv` 的 STRM，仅同步 `/A` 且开启清理，返回 `removed=1`，B 的 STRM 被删除。
- 影响：删除的是本地 STRM 与索引，未验证也未声称会删除远端视频。
- 修复方向：清理范围与同步范围一致，规范化路径并按路径边界判断；不同目标目录的同步互不清理。

### F2 · P1 · 读取失败和深度截断没有完整传递给清理阶段

- 位置：`app/services/strm_sync.py:144`，尤其 `:145`、`:154` 附近。
- 目录请求异常只返回空列表；达到递归深度上限也返回空列表，都没有设置不完整标记。
- 复现：根目录有可读视频与 `/broken` 子目录，子目录抛出模拟超时；同步返回 `truncated=False`，旧的 broken 子目录 STRM 被清理。
- 修复方向：将失败、超深、超时等统一纳入扫描完整性结果；不完整扫描不做推断性删除。真正空目录的清理也应有明确行为，不能混同请求失败。

### F3 · P1 · 匿名播放依赖可枚举的自增 ID

- 位置：`app/api/routers/strm.py:57`、`app/services/strm_sync.py:61`、`app/db/base.py:37`。
- 文件头声称依靠“ID 不可枚举猜测”，实际是整数自增主键；解析直链没有播放凭据校验。
- 隔离验证：无认证请求 `/api/v1/strm/play/1`，用假换链服务可直接得到 302。
- 影响：能访问该端点的人可以尝试枚举播放记录；本轮没有测试公网部署，也没有声称发生实际泄露。
- 修复方向：稳定的签名播放地址或随机播放凭据，绑定记录并可轮换/吊销；保留媒体服务器无需 JWT 的播放能力。旧 STRM 重写/迁移纳入本任务，不能永久保留匿名整数兼容入口。

### F4 · P1 · 洗版收尾与已入库索引冲突

- 位置：`app/services/library.py:267`、入库后 `:211` 附近；`app/services/upgrade.py:220`。
- 入库先登记新路径；随后 `replace_library_file` 把旧记录改成这个已存在的新路径，与 `library_files.path` 唯一约束冲突。
- 复现：旧、新文件均存在且已建索引，替换抛出 `IntegrityError`。
- 修复方向：保留新记录、合并质量与洗版次数、清理旧记录；验证新文件实际可用之后才删除旧文件。删除失败需保留可重试状态，不能只更新索引后丢失跟踪。
- 现有测试主要测试替换助手，没有覆盖完整“新文件登记 → 洗版收尾”的组合。

### F5 · P1 · 并发自动下载投递没有统一幂等边界

- 位置：`app/services/download.py:32`、`:78`、`:112`、`:138`。
- 查询已有任务后，先 await 外部投递，再写任务；两个入口可以同时通过检查。订阅服务局部的 `_inflight` 不覆盖雷达/RSS 等其他调用者。
- 复现：相同订阅、相同链接并发两次，假下载器被调用两次，任务表插入两行。
- 修复方向：在下载服务内统一原子占位和资源键；明确单进程并发与重启后重试语义，外部调用在占位成功之后执行。已有重复行须有保守处理，不能删除进行中的真实任务。

### F6 · P2 · 周期配置有两套可写来源

- 位置：`app/services/config_store.py:94`、`:278`；`app/services/scheduler.py:246`、`:433`。
- 设置页保存 `runtime_config`，定时任务页保存 `schedules`；后者覆盖前者。
- 复现：`SUBSCRIBE_INTERVAL_MINUTES=5`，但已存调度覆盖为 90 分钟时，`effective_schedule` 仍返回 90。优先级有实现，但界面修改“已生效”的承诺容易与实际执行周期冲突。
- 修复方向：调度周期只保留一个权威写入口；旧键迁移后作为兼容读取，界面统一展示真实生效值与来源。
