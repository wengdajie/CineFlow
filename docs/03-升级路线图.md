# 03 · 升级路线图

> 状态标记：`规划中` / `进行中` / `已完成` / `已放弃`
> 每个已完成项必须写清**验收证据**（哪条命令/测试证明它可用）。

## 总目标

把 CineFlow 从「能自动追剧的工具」升级为**日常真正可用的家庭影视中枢**：

1. 网盘资源不再需要人工去网盘点转存 → **自己会转存、能浏览网盘**
2. 不用打开电脑开网页 → **在飞书/钉钉/TG 里发一句话就能搜和下**
3. 配置不用翻代码 → **界面上看得见、该改的地方有入口**
4. 项目可被他人接手 → **文档齐全、每步可 review**

5. 网盘里的片子不必占 NAS 空间 → **STRM 直连播放**
6. 媒体服务器不再猜片名 → **自动刮削 NFO**

**v1.3.0 结论：M1~M4 全部交付并实测通过。**
**v1.4.0 结论：M5~M10 全部交付并实测通过**（对标调研见
[09-竞品对标与差距分析.md](09-竞品对标与差距分析.md)）。

## v1.5.0 候选（规划中，尚未排期）

输入来自 [01-项目现状 §5 缺口](01-项目现状.md) 与
[09-竞品对标与差距分析](09-竞品对标与差距分析.md)：

| 候选项 | 动机 | 前置条件 |
|---|---|---|
| 设置页可编辑并热生效 | ADR-05 的遗留：当前 12 组 62 项只读 | 需先设计「表值 vs 环境值」双来源判定，避免显示与生效不一致 |
| 多用户与权限分级 | 当前仅单管理员，无法给家人开只读账号 | `users` 表已有，需加角色与端点级鉴权 |
| 下载器负载均衡与失败自动换源 | 单下载器挂了整条链路停 | 需下载器健康状态模型 |
| 站点 Cookie 自动保活与掉线告警 | Cookie 过期表现为静默 0 结果 | 需站点级健康探测定时任务 |
| STRM 播放策略改写（对标 MediaWarp） | 现在只做 302，不改写字幕/转码策略 | 需介入媒体服务器 API 而非仅跳转 |
| TG 频道资源采集（对标 TgtoDrive） | 部分资源只在 TG 频道发布 | 需长连接监听与限流，运行模型与现有定时巡检不同 |
| 移动端 PWA 离线壳 | 手机上用起来别扭 | 前端零依赖约束下需手写 service worker |
| 更多网盘直连（115 / 迅雷 / PikPak） | AList、WebDAV 覆盖不到的场景 | 各家私有 API，逐个适配，维护成本高（见 ADR-02） |
| ChatOps 富交互（按钮卡片） | 目前只有纯文本 | 各平台卡片协议差异大，需扩展 `ChatAdapter.reply` |
