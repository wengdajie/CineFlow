# 深度审查与本地验证（2026-10-18）

本轮围绕可复现故障做多轮审查，覆盖认证和凭据、下载任务生命周期、文件整理与移动、订阅并发、站点编辑、前端链接及依赖。已修复本轮确认的问题；最后复核未再发现新的可复现阻断问题。这是本轮审查范围内的结论，不能证明项目不存在其他缺陷。

## 已修复的问题

| 范围 | 原有问题 | 修复后的行为 |
|---|---|---|
| 文件覆盖 | 整理先删除旧文件，复制失败会丢失旧媒体；源目标相同可能删除源文件 | 同目录临时文件完成后再替换，失败保留源文件和旧媒体，同文件安全处理 |
| 跨盘移动 | 覆盖旧目标后再移动，失败无法恢复 | 文件通过暂存发布；目录先备份旧目标，失败恢复，未完成的新目录保留供恢复 |
| 路径边界 | 绝对命名模板、符号链接可能越过配置根目录 | 媒体及 STRM 目标均检查解析后的根目录边界 |
| 根目录保护 | 本地网盘根目录可删除、重命名、移动；媒体库根目录可移动或重命名 | 拒绝对配置根目录的这些操作 |
| 部分入库 | 多文件任务中一个文件成功就标记整个任务已入库 | 全部文件成功后才完成；重试识别此前确实成功的文件并继续剩余文件 |
| 库索引 | 覆盖移动后保留旧目标元数据，出现重复索引 | 同步移除被替换目标的索引，再更新源文件索引 |
| 字幕 | 宽松前缀匹配会混入相邻集数的字幕，大小写差异丢失语言后缀 | 按完整媒体名和分隔符匹配，保留语言后缀 |
| STRM | 直接覆盖写入，失败损坏原有文件；相对源地址不稳定 | 暂存后替换，失败保留旧版本，写入绝对源地址 |
| 下载器归属 | 已删除或改名的下载器会回退到其他实例，可能操作错误任务 | 历史任务严格匹配实例名称；下载器改名同步更新任务归属 |
| 投递竞态 | 手动下载尚未登记就提交外部下载器；并发删除可能留下孤立任务 | 先持久化提交状态；提交后发现已删除则撤回所有新 GID，不删除文件 |
| 删除任务 | 下载器未确认删除时仍删除数据库记录 | 失败保留任务供重试；aria2 必须独立确认 GID 已不存在才按幂等成功处理 |
| 同步竞态 | 较早开始的下载器查询会把已入库任务改回下载中 | 忽略已入库、已取消或外部任务 ID 已变化的过期响应 |
| 完成判断 | 进度 100% 会覆盖明确的失败、暂停、校验中状态 | 仅明确的完成状态可以触发整理 |
| 订阅并发 | 网盘和视频订阅手动检查与定时检查可同时执行 | 同一订阅检查期间不重复执行，异常时释放运行标记 |
| 视频统计 | 创建了失败任务仍计入下载成功数量 | 失败任务计入失败数量 |
| 站点修改 | 重名返回数据库错误；必填字段显式 null 导致异常 | 重名返回 409，非法 null 返回 422 |
| 凭据返回 | options、URL Basic Auth 和查询参数中的凭据明文返回前端 | 敏感字段掩码展示，编辑回填保留原值，不破坏搜索模板 |
| 管理员鉴权 | 静态 API Token 可选中已禁用管理员 | 仅使用启用的管理员，令牌使用恒定时间比较 |
| 密码处理 | 相同密码生成相同盐；异常哈希可能引起登录 500 | 每次生成随机盐，兼容旧哈希，异常哈希安全拒绝 |
| 密码修改 | 原密码和新密码放进 URL，可能进入访问日志 | API 和前端改为 JSON 请求体；旧查询参数形式不再接受 |
| 日志 | HTTP 错误和访问 URL 可能包含密码、Token 或 API Key | 文件、控制台、内存缓冲中的相关 URL 与敏感查询参数脱敏 |
| JWT 默认密钥 | 内置默认值及部署模板使用公开固定值 | 空值和已知公开占位串自动生成本机随机密钥，持久化至数据目录；自定义密钥保留 |
| JWT 依赖 | python-jose 及 ecdsa 被当前依赖审计报告命中 | 迁移至 PyJWT，固定 HS256，要求 sub/exp；保留聊天机器人实际使用的 cryptography |
| TLS | HTTP 客户端及部分下载器、网盘驱动默认关闭证书校验 | 默认校验证书；需要自签名服务时可通过对应驱动 options 显式配置 verify_ssl |
| 前端链接 | 外部详情页允许 javascript 等可执行协议 | 链接构造及打开前仅接受 HTTP/HTTPS，浏览器实测阻止恶意链接 |
| 网盘配置 UI | 站点分类漏掉网盘存储，编辑账号不能正确选中类型 | 补齐分类名称及图标，阿里云盘账号可正确编辑 |

- 两套 Python 的已安装依赖审计均未报告已知漏洞。审计是当时数据库的结果，不表示不存在尚未披露的问题。
- 隔离 Chromium：热榜一次点击只发送 1 次搜索，首条结果约 **272 ms** 可见，显示“搜索中 1/2 站”时已有资源；慢站点随后补齐。恶意详情链接被阻止，站点凭据展示为掩码、编辑令牌保存成功，390 像素宽页面没有整体横向溢出，脚本错误与异常弹窗均为 0。
- 隔离浏览器修改测试账号密码：请求 URL 不含密码，JSON 请求体提交成功，新密码重新登录成功。此测试没有修改真实管理员账号。
- 真实本机 aria2：测试 HTTP 服务强制要求 Cookie、Referer、User-Agent，两个文件（253952 / 106496 字节）完成下载，大小和 SHA-256 与源数据一致，子目录保留。测试使用独立临时目录，已移除下载器测试任务。
- 实际启用站点搜索“死神”：开始事件 1.094 秒，首批 40 条资源 **10.812 秒**返回，全部站点 39.437 秒结束。说明首批资源无需等待全部站点；真实站点响应时间仍受网络影响，本次不能据此声称所有站点都变快。
- 最新本地服务健康与登录均返回 200；aria2、qBittorrent、yt-dlp 的连通检查均成功。8 个存储 Provider 可见，下载默认模式仍为 download，临时夸克任务正确提示夸克账号要求，转存记录增量为 0，临时任务已删除。原有 **8 条已入库任务**保持不变。

回归文件主要为 `tests/test_deep_review.py` 和 `tests/test_auth_review.py`。本地测试证据保存在 Git 忽略的 `.tmp/deep-review/`：全量测试日志、依赖审计 JSON、`browser-result.json`、截图、`aria2-result.json`、`runtime-result.json`、`timing.json`。审查前数据库与配置也已在该目录备份，实际文件未用于破坏性验证。

## 升级与兼容性

- **⚠️ 修改密码接口变更**：`POST /api/v1/auth/password` 使用 JSON 对象 `{old_password, new_password}`，不再使用 URL 查询参数；前端已同步更新。
- **⚠️ 默认签名密钥迁移**：使用公开默认值或已知占位串的实例升级后，旧登录令牌失效，需要重新登录。自定义密钥保持原值，使用相同自定义密钥的旧 python-jose 令牌已有兼容性回归。备份数据目录时应包含 `jwt-secret.txt`；该文件损坏时拒绝回退到公开密钥。
- 密码哈希的随机盐仅作用于新建或修改的密码，现有密码仍可登录。
- TLS 默认校验可能暴露原先被忽略的证书配置错误。应优先配置有效证书或受信任 CA；明确需要关闭时，由对应驱动 options 配置 `verify_ssl: false`。
- 无容器运行环境，本轮没有构建或运行 Docker 镜像；部署文件只完成静态验证。
