# 15 · 常见问题 FAQ

> README 里的常见问题合集。
> 部署类问题请转 [07-运维手册.md](07-运维手册.md) 与 [11-飞牛NAS部署指南.md](11-飞牛NAS部署指南.md)。

## ❓ 常见问题

<details>
<summary><b>下载完成了但没有入库？</b></summary>

99% 是**路径不一致**。CineFlow 需要能直接访问下载器落盘的文件。
请确认 CineFlow 容器的 `/downloads` 与下载器容器的 `/downloads` 指向宿主机同一目录。
可在「运行日志」页搜 `未找到下载文件` 确认。
</details>

<details>
<summary><b>硬链接失败 / 提示已降级为复制？</b></summary>

硬链接要求源和目标在**同一文件系统**。请把 `downloads` 与 `library` 放在同一个卷
（如群晖同一个 `/volume1`）。做不到就设 `CF_TRANSFER_MODE=copy`。
</details>

<details>
<summary><b>没有 TMDB API Key 能用吗？</b></summary>

能。解析引擎是纯本地的，搜索、过滤、下载、命名、入库全部正常，
只是没有海报、简介，且「总集数」需要你在订阅时手填。
</details>

<details>
<summary><b>搜索结果为空？</b></summary>

依次检查：① 站点管理里有没有**启用**的索引器/盘搜（示例站点默认全禁用）；
② 点「测试」看连通性；③ 看「运行日志」页；④ 是否被 `EXCLUDE_KEYWORDS` 或 `MIN_SEEDERS` 过滤光了。
</details>

<details>
<summary><b>网盘资源怎么下载？</b></summary>

网盘分享链接无法交给 BT 下载器。CineFlow 会登记为待处理任务并保留提取码，
你可以在「下载任务」页点按钮手动转存；或启用 `pan_transfer` 插件，
配置一个转存 Webhook（如自建 alist / cloud-saver 服务）实现全自动。
</details>

<details>
<summary><b>忘记密码了？</b></summary>

删掉 `data/cineflow.db` 里的 users 表记录，或直接删库重启（会丢历史数据）；
也可以设 `CF_SUPERUSER` 为一个新用户名后重启，会自动创建新管理员。
</details>

<details>
<summary><b>群晖 / 威联通文件权限报错？</b></summary>

在 compose 里把 `PUID` / `PGID` 改成你的实际用户（SSH 执行 `id` 查看），
并确保该用户对挂载目录有读写权限。
</details>

<details>
<summary><b>视频追更一直没有新视频？（v1.12.0）</b></summary>

按这个顺序查：

1. **先用「预览」**：它不落库，直接告诉你能不能解析、拿到几条。
2. **首次检查故意不下载**：勾了「跳过已有」时首检只登记 ID，**第二轮**才开始下新的。
3. **B 站拿不到标题**：yt-dlp 扁平提取对 B 站只返 ID，所以**标题过滤规则在 B 站上等于不生效**
   （设计上放行）。靠标题控量的话，B 站请改用 `max_per_run`。YouTube 正常。
4. **可能被自动暂停了**：连续 5 次失败自动 `paused`，修好后点「重置失败计数」。
5. **失败的视频不会自动重试**（否则会堵死队列），要重试请手动下载那一条。

详见 [07-运维手册.md](07-运维手册.md) §9.2。
</details>

<details>
<summary><b>配了限速时段却没生效？（v1.12.0）</b></summary>

常见三种情况：

- **等下一轮**：`cineflow.speed_limit` 是 10 分钟一轮，不想等就点卡片上的「立即应用」。
- **下载器不支持**：迅雷与 yt-dlp 没有全局限速接口，结果里会如实显示 `skipped`，不是故障。
- **版本太老**：`23:00-07:00` 这种**跨午夜**区间在 v1.12.0 之前恒不生效（朴素比较的经典 bug），升级即可。

反过来，如果你想在下载器里手动管限速，请把 `CF_SPEED_LIMIT_INTERVAL_MINUTES`
设为 `0` 关掉这个任务——否则你手动调的值会在 10 分钟内被时段值盖掉（幂等下发）。
</details>

<details>
<summary><b>新番日历是空的 / 封面全白？（v1.12.0）</b></summary>

- **整个空**：`api.bgm.tv` 不通。`curl https://api.bgm.tv/calendar` 验证；不通则该页签不可用，不影响其他页签。
- **有条目但封面全白**：你走 HTTPS 访问，而封面原始地址是 `http://`（实测 113/113 都是）。
  v1.12.0 已统一改写为 `https://`；仍白就检查 `bgm.tv` 是否在图片代理白名单里。
- **显示日文名**：该番 Bangumi 上没有中文名（约 10%），回退日文原名是正常行为。
</details>

<details>
<summary><b>升级后封面比以前少了？（v1.12.0）</b></summary>

是刻意的。豆瓣匹配加了 **60 分门槛 + 年份校验**，匹配不确定时**返回空而不是硬给一张**。
错封面会让人下错片子，空白封面一眼就知道是缺数据。

想看某条为什么没匹配上，接口会返回 `match_score` / `match_confidence`：

```bash
curl -H "X-API-Token: your-token" \
  "http://127.0.0.1:6060/api/v1/trending/douban?title=片名&year=2024"
```
</details>

<details>
<summary><b>通知太吵，能只收失败吗？（v1.12.0）</b></summary>

能。在渠道的 options 里加 `events` / `events_exclude` / `min_level`：

```json
{"events": ["download.failed", "site.unhealthy"], "min_level": "warning"}
```

支持前缀通配，`download.*` / `download.` / `download` 三种写法等价
（v1.12.1 起；此前只认带尾点的 `download.`，按 `download.*` 配会一条都收不到）。
**三个都不填 = 全收**（老配置行为完全不变）。
同一条告警的重复间隔由 `CF_NOTIFY_ALERT_COOLDOWN_MINUTES`（默认 360 分钟）控制。
事件名写错不会报错，只会静默收不到 —— 合法名见
[开发指南 → 可订阅事件](14-开发指南.md#可订阅事件)。
</details>
