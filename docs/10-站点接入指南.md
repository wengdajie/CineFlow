# 10 · 站点接入指南（BT / 网页站 / JSON API 站）

> 本篇回答一个具体问题：**「我手上有一个站，怎么让 CineFlow 能搜到它？」**
> 全篇按「先跑通、再调字段」的顺序写，每一步都给出可复制的配置和自检方法。
>
> 前置：服务已起在 `http://<IP>:6060`，用管理员账号登录（默认 admin / cineflow）。
> 只有 **管理员** 能新增/修改站点（普通用户只能搜索，见 ADR-19）。

---

## 0. 先选对 Provider：五条路，别走错

CineFlow 不去猜站点长什么样，而是要你选一个**适配器（Provider）**。
选错 Provider 是新手最常见的失败原因，先对着这张表定位：

| 站点长什么样 | 选哪个 Provider | 难度 | 说明 |
|---|---|---|---|
| 有 Torznab 接口（Jackett / Prowlarr 代理出来的） | `torznab` | ★ 最省事 | **强烈推荐的主路径**，几百个 PT/公开站都能这么接 |
| 有 RSS / 种子订阅源 | `rss` | ★ | 只需一个 URL |
| 有 JSON 接口（F12 能看到 `/api/xxx` 返回 JSON） | `api_generic` | ★★★ | 要写字段映射 |
| 只有网页（F12 看到的是 HTML 表格/列表） | `html_generic` | ★★★★ | 要写正则 |
| 动漫专站 Nyaa | `nyaa` | ★ | 内置，填 URL 即可 |
| 在线影视站（`/index.php/vod/...`） | `maccms` | ★ | 只填域名。⚠️ 只做索引，约 92% 是会员正片下不了，见 0c |

> **判断方法**：浏览器打开站点搜索页 → F12 →「网络（Network）」→ 筛选 `Fetch/XHR`
> → 重新搜一次。
> * 列表里出现返回 JSON 的请求（响应是 `{...}`）→ 走 `api_generic`，把这个请求的
>   URL、参数、响应结构记下来。
> * `Fetch/XHR` 一片空白，内容全在 `Doc` 那条 HTML 响应里 → 走 `html_generic`。

## 0b. 让 AI 帮你选（v1.13.0，可选）

如果你看完上面那张表还是不确定选哪个、字段怎么填，可以让内置 AI 先看一眼：

**站点管理 → 「AI 分析站点」→ 填站点首页地址 → 开始分析**

它会抓一页首页 + 试探两个常见搜索路径，然后告诉你：
用哪个 Provider、字段怎么填、置信度多少、依据是什么。

**但请务必按三步走，不要跳过第二步**：

| 步骤 | 做什么 | 为什么不能跳 |
|---|---|---|
| ① 开始分析 | AI 给出适配器 + 字段配置 + 置信度 + 依据 | — |
| ② **试跑验证** | 按这份配置**真去站点搜一次**，告诉你命中几条 | 模型「说得很像」但字段填错是常态。不验就添加，等于把一个搜不到东西的站塞进搜索链路，之后**每次搜索都白等它一次超时** |
| ③ 添加为站点 | 落库，且**默认不启用** | 让你自己再点一次「测试」确认连通性 |

**前置条件**：内置 AI **默认是关的**（开启才会把页面正文发给模型），
先到「设置 → 内置 AI」打开开关并填接口地址 / 模型 / 密钥。
支持任何 OpenAI 兼容接口（OpenAI / DeepSeek / 通义 / Ollama / OneAPI…），
本地模型（Ollama）密钥可留空。详见
[docs/12 · 内置 AI](12-功能特性详解.md)。

> 试搜 0 条**不一定**是配置错，也可能这个站真没有你搜的那部片。
> 提示里会把两种可能都说出来，建议换个热门片名再试一次。
> 置信度低于 70% 的建议尤其要先验证再添加。

## 0c. 路径 E：在线影视站（MacCMS）——先看清能力边界

`bzzdyy.com` / `cz4k.com` 这类「在线影视站」大多用 MacCMS（苹果 CMS）搭建，
URL 结构固定，所以**接它只需要填一个域名**：
「站点管理 → 从模板添加 → 在线影视站（MacCMS）」，把 `url` 改成你的站点域名即可
（`max_items` 控制一次最多抓几部片的详情，默认 6，调大会明显变慢）。

**但你必须先知道它能给你什么。** 我们对 bzzdyy 实测统计
（首页 30 部片 / 53 个播放源）：**约 92% 是腾讯 / 爱奇艺 / 优酷 / 芒果的会员正片**。

这类站**自己不存片**，播放页里的地址就是各平台官方地址；
它们看起来「什么都能播」是因为把播放交给一个 **VIP 解析网关**
（依赖盗取或共享的会员票据）。**CineFlow 不接这个网关**
（[ADR-24](04-决策记录.md) / ADR-68）。

所以实际效果是：

- ✅ 能当索引用：告诉你「这部片在哪些平台有」；
- ✅ B 站内容 / UP 主自制 / 官方免费片源 → 正常下载；
- ⚠️ 会员正片 → 打「会员」标签、**不显示下载按钮**，只能点进官方平台看。

**搜到很多、能下的少是正常的**，不是配置错了，不用反复折腾。

> `cz4k.com` 实测被 SafeLine WAF 拦在门外（HTTP 468，换 UA / 语言头无效），
> 直连不可用、需自备代理。本项目**不做 WAF 对抗**，所以只保留预设。

## 1. 路径 A：Torznab（推荐，覆盖绝大多数 BT 站）

Torznab 是 BT 索引器的通用协议。你不需要为每个 PT 站写适配，
装一个 **Jackett** 或 **Prowlarr**，由它去对接各站，再统一吐 Torznab 给 CineFlow。

### 1.1 装 Jackett

`docker-compose.yml` 里已经带了 Jackett（注释状态），去掉注释即可：

```yaml
  jackett:
    image: lscr.io/linuxserver/jackett:latest
    container_name: jackett
    restart: unless-stopped
    ports:
      - "9117:9117"
    environment:
      PUID: 1000
      PGID: 1000
      TZ: Asia/Shanghai
    volumes:
      - ./jackett:/config
```

```bash
docker compose up -d jackett
```

打开 `http://<NAS_IP>:9117`，在 Jackett 里 **Add Indexer** 添加你要的站点
（私有站要填该站的用户名/密码或 Cookie，这一步在 Jackett 里做，不在 CineFlow 里做）。
添加完点该 indexer 的 **Copy Torznab Feed**，会得到一个地址。

### 1.2 拼出给 CineFlow 用的地址

格式固定为：

```
http://<jackett地址>:9117/api/v2.0/indexers/<indexer-id>/results/torznab
```

* `<indexer-id>` 就是 Jackett 里那个站的 id（如 `nyaasi`、`mteam`、`btsow`）。
* **想一次接入 Jackett 里所有站**，把 id 写成 `all`：

```
http://127.0.0.1:9117/api/v2.0/indexers/all/results/torznab
```

> ⚠️ **容器互访要用服务名，不要用 127.0.0.1**。CineFlow 和 Jackett 都在
> compose 网络里时，地址应写 `http://jackett:9117/...`。写 `127.0.0.1` 指的是
> CineFlow 容器自己，必然连不上——这是排障时最常见的一处错。
> 首次启动预置的示例站点用的是 `http://127.0.0.1:9117/...`，那是给源码直跑场景的，
> 用 Docker 时记得改成 `jackett`。

### 1.3 在 CineFlow 里添加

「站点管理」→「新增站点」：

| 字段 | 填什么 |
|---|---|
| 名称 | 随便起，会显示在搜索结果的来源列，建议写站名 |
| 类型（kind） | `indexer` |
| Provider | `torznab` |
| 地址（url） | 上一步拼出来的 torznab 地址 |
| API Key | Jackett 首页右上角的 **API Key** |
| 启用 | 打开 |

`options` 可选项（`torznab` 只认这两个，别多填）：

```json
{
  "category": "2000,5000",
  "page_size": 100
}
```

* `category`：Torznab 分类号，逗号分隔。`2000`=电影、`5000`=电视剧、`5070`=动漫。
  不填就是全分类（推荐先不填，跑通再收窄）。
* `page_size`：单次请求条数，默认够用，站点报错时再调小。

添加完点该站的 **「测试」** 按钮。返回「搜索连通」就成了。

## 2. 路径 B：RSS 源

最简单的一类。Provider 选 `rss`，地址填 RSS 的完整 URL，需要 Cookie 的填 Cookie。
`options` 无需配置。

适用场景：站点提供「最新种子 RSS」。注意 RSS 通常**不支持关键词搜索**，
它的价值在于**追新雷达**（定时拉最新流，见 `docs/07` §4）。

## 3. 路径 C：`api_generic`（JSON 接口站）

这是接自定义站点的主力适配器。**它的全部能力都靠 `options` 里的字段映射描述，不用改代码。**

### 3.1 先把接口摸清楚

用 F12 抓到搜索请求后，你需要回答四个问题：

1. 接口地址是什么？（拆成「不变的前缀」+「路径」）
2. 关键词是哪个参数名传的？
3. 响应里，资源列表在哪个字段下？（可能嵌好几层）
4. 列表项里，标题/链接/大小分别叫什么字段名？

### 3.2 一阶段站点（搜索接口直接给下载链接）

最常见的形态。假设抓到：

```
GET https://example.com/api/v1/search?kw=庆余年&page=1
→ {"code":0,"data":{"list":[{"name":"庆余年 S01","magnet":"magnet:?xt=...","filesize":"12.3 GB"}]}}
```

对应 `options`：

```json
{
  "api_base": "https://example.com/api/v1",
  "search_path": "search",
  "query_key": "kw",
  "page_key": "page",
  "page_base": 1,
  "list_path": "data.list",
  "success_key": "code",
  "success_value": 0,
  "item_map": {
    "title": "name",
    "link": "magnet",
    "size": "filesize"
  },
  "health_keyword": "庆余年"
}
```

### 3.3 两阶段站点（搜索只给条目，链接在详情里）

不少影视站的搜索接口只返回「影片」，种子得再请求一次详情。这类要配 `detail_*`：

```json
{
  "api_base": "https://example.com/api",
  "fixed_params": {"app_id": "xxx", "identity": "yyy"},
  "search_path": "getVideoList",
  "query_key": "sb",
  "list_path": "data.data",
  "item_map": {"detail_id": "idcode", "title": "title", "year": "years"},
  "detail_path": "getVideoDetail",
  "detail_query_key": "id",
  "detail_extract": [
    {
      "list_path": "data.all_seeds",
      "kind": "magnet",
      "map": {"title": "zname", "link": "zlink", "size": "zsize"}
    }
  ],
  "max_detail_items": 8
}
```

> `max_detail_items` 限制「为多少个搜索结果去拉详情」。这个值别调大：
> 每个条目都是一次额外 HTTP 请求，调到 50 会让一次搜索变成 50 个请求，
> 既慢又容易被站点限流封 IP。默认值是权衡过的。

### 3.4 `options` 逐字段说明（`api_generic`）

**接口定位**

| 键 | 含义 | 默认 |
|---|---|---|
| `api_base` | 接口前缀。不填则用站点的 `url` 字段 | 站点 url |
| `site_url` | 站点主页（用于拼相对链接、生成详情页地址） | 站点 url |
| `search_path` | 搜索接口路径，会拼到 `api_base` 后面 | 无 |
| `method` | `GET` 或 `POST`（少数站要 POST） | `GET` |
| `headers` | 额外请求头，字典 | `{}` |
| `auth_header` | 认证头名（如 `Authorization`），值取站点的 API Key | 无 |
| `api_key_param` | 若 Key 走 URL 参数，填参数名（如 `apikey`） | 无 |
| `fixed_params` | 每次请求都要带的固定参数（`app_id` 之类） | `{}` |

**请求参数**

| 键 | 含义 | 默认 |
|---|---|---|
| `query_key` | 关键词参数名 | `keyword` |
| `page_key` | 页码参数名，不填则不翻页 | 无 |
| `page_base` | 首页是 0 还是 1（**填错会漏掉第一页**） | `1` |
| `limit_key` / `limit` | 每页条数的参数名与值 | 无 |
| `media_type_param` / `media_type_map` | 电影/剧集分开搜时的类型参数与取值映射 | 无 |

**响应解析**

| 键 | 含义 | 默认 |
|---|---|---|
| `list_path` | 资源列表位置，点号路径，如 `data.list`、`result.items.0.rows` | `data` |
| `success_key` / `success_value` | 成功标志字段与期望值（如 `code` / `0`）。**配上它，站点报错时日志才会说人话**，否则只会看到「0 条」 | 无 |
| `message_key` | 错误信息字段名（如 `msg`），用于把站点的报错原文带进诊断 | 无 |
| `item_map` | 列表项字段映射，见下 | 见下 |
| `media_map` | 作品级信息映射（封面/评分/年份），榜单画封面墙用 | 见下 |

**`item_map` 可映射的目标字段**（左边是 CineFlow 的字段，右边填站点的字段名）

| 目标字段 | 用途 | 不填会怎样 |
|---|---|---|
| `title` | 资源标题 | **必填**，否则整条被丢弃 |
| `link` | 磁力/种子/网盘链接 | **必填**（两阶段站点例外，链接在 `detail_extract` 里） |
| `size` | 文件大小，支持 `12.3 GB` 这种字符串 | 无法按体积过滤/排序 |
| `seeders` / `leechers` | 做种/下载数 | 无法按热度排序，优选会退化 |
| `page_url` | 详情页地址 | 界面里点不开原页面 |
| `password` | 网盘提取码 | 网盘资源转存会失败 |
| `publish_at` | 发布时间 | 无法按新旧排序 |
| `description` | 描述 | 少一点展示信息 |
| `detail_id` | 条目 ID（两阶段站点必填） | 拉不到详情 |

`media_map` 的默认映射已经照着常见影视站的字段名写好了
（`image`/`doub_score`/`years`/`class`/`abstract`/`performer`…），
很多站不用配就能出封面和评分。字段名不一样时按需覆盖。

**追新雷达（可选但值得配）**

| 键 | 含义 |
|---|---|
| `latest_path` | 「最新发布」接口路径 |
| `latest_list_path` | 最新流的列表位置（不填则复用 `list_path`） |
| `latest_map` | 最新流的字段映射（不填则复用 `item_map`） |
| `latest_params` | 多组参数变体，列表。例：分别拉电影和剧集两个榜 |
| `latest_pages` | 拉几页 |

配了 `latest_path`，这个站就会被 15 分钟一次的追新雷达纳入巡检
（`CF_RADAR_INTERVAL_MINUTES`），订阅的新剧能更快被发现。

**自检**

| 键 | 含义 |
|---|---|
| `health_keyword` | 健康检查用的探测词。**建议一定填**，填了「测试」按钮才会真搜一次；不填只校验配置完整性，Cookie 过期这类问题查不出来 |

## 4. 路径 D：`html_generic`（只有网页的站）

没有 JSON 接口时用它，靠正则从 HTML 里抠字段。

### 4.1 最省事的用法：只抓磁力链

如果站点的搜索结果页把磁力链直接写在页面里，什么正则都不用写：

```json
{
  "search_url": "https://example.com/search?q={keyword}&page={page}",
  "magnet_only": true,
  "local_filter": true
}
```

`magnet_only` 会自动抓页面里所有 `magnet:?xt=urn:btih:...`。
标题从磁力链的 `dn=` 参数取。`local_filter` 让 CineFlow 本地按关键词再筛一遍
（站点搜索不准时很有用）。

### 4.2 标准用法：行正则 + 字段正则

两层结构：`row_pattern` 先把页面切成「一行一个资源」，
再在每行里用 `field_patterns` 抠字段。

```json
{
  "search_url": "https://example.com/search?q={keyword}&page={page}",
  "latest_url": "https://example.com/latest",
  "row_pattern": "<tr class=\"item\">(.*?)</tr>",
  "field_patterns": {
    "title": "title=\"([^\"]+)\"",
    "link": "href=\"(magnet:[^\"]+)\"",
    "size": "<td class=\"size\">([^<]+)</td>",
    "seeders": "<td class=\"se\">(\\d+)</td>"
  },
  "max_rows": 60,
  "health_keyword": "流浪地球"
}
```

规则：

* `{keyword}` 和 `{page}` 是占位符，会被自动替换（关键词已 URL 编码，不要自己再编码一遍）。
* 每个正则**取第一个捕获组**；没有捕获组时取整段匹配。
* 正则写错**不会让整站挂掉**，只是该字段取空 + 日志一条 warning（有意的降级设计）。
* 想从详情页取链接（列表页只有详情链接时），配 `detail_link_field` 指向详情页 URL 字段，
  再用 `max_detail_items` 限制抓几个详情页。

### 4.3 `options` 逐字段说明（`html_generic`）

| 键 | 含义 |
|---|---|
| `search_url` | 搜索页 URL 模板，含 `{keyword}` / `{page}` |
| `latest_url` | 最新页 URL（追新雷达用） |
| `row_pattern` | 行切分正则 |
| `field_patterns` | 字段正则映射（`title`/`link`/`size`/`seeders`/…） |
| `magnet_only` | 忽略上面两项，直接全页抓磁力 |
| `local_filter` | 本地按关键词再过滤一遍 |
| `kind` | 强制资源类型（`magnet`/`torrent`/`pan`），不填自动推断 |
| `max_rows` | 单页最多取几行 |
| `latest_pages` | 最新页翻几页 |
| `page_base` | 首页页码是 0 还是 1 |
| `headers` | 额外请求头 |
| `referer` | Referer 头（**防盗链站必填**，不填常见表现是 403 或 0 结果） |
| `site_url` | 站点主页，用于把相对链接补全成绝对链接 |
| `health_keyword` | 健康检查探测词 |

## 5. Cookie 怎么拿（私有站/防爬站必读）

PT 站和一部分公开站要求登录态。**表现很有欺骗性**：站点首页能打开、
「测试」也可能显示连通，但搜索永远 0 条。

取 Cookie 的步骤：

1. 用浏览器**正常登录**该站点。
2. F12 打开开发者工具 →「网络（Network）」标签。
3. 刷新页面，点列表里**第一条**请求（通常是文档本身）。
4. 右侧「标头（Headers）」→ 找「请求标头」里的 `Cookie:` 那一行。
5. **整行值**复制（形如 `c_secure_uid=xxx; c_secure_pass=yyy; ...`），
   粘到 CineFlow 站点编辑页的 **Cookie** 字段。

注意事项：

* Cookie 有有效期，过期后同样表现为 0 结果。定期在「站点健康」页看有没有变
  **亚健康（degraded）**——那一栏专门抓这种「能连但搜不出」的情况。
* 别把 Cookie 贴到 `options` 的 `headers` 里再重复一遍。站点的 Cookie 字段会自动
  注入请求头，两处都写只会互相覆盖，反而更难排查。
* Cookie 属于登录凭据，等同密码。CineFlow 的 API 返回站点列表时会打码，
  不会把明文 Cookie 下发到前端。

### 5.1 遇到 403 的站（如 hdzu 一类）

有些站对非浏览器请求直接返回 **403**。这不是 bug，是站点的反爬策略。处置顺序：

1. **补 Cookie**：按上面的步骤取一份登录态 Cookie 填进去，多数情况就通了。
2. **补 Referer**：`options` 加 `{"referer": "https://hdzu.org/"}`。有的站校验来源页。
3. **补 UA 等头**：`options` 加

   ```json
   {"headers": {"Accept-Language": "zh-CN,zh;q=0.9"}}
   ```

4. 仍然 403 → **禁用这个站**。

> 关于第 4 条的立场：CineFlow **不做验证码识别、不做 JS 挑战破解、不逆向签名算法**
> （见 ADR-34）。这类对抗一定会打输，还会连带把你的 IP 和账号搞封。
> 站点明确不欢迎程序访问时，正确做法是不访问它，而不是绕过它。
> 同理，夸克网盘的扫码登录也因为需要逆向签名公参而**不做**（ADR-38）。

## 6. 加完站点后怎么验证（按顺序做）

**第一步：点「测试」按钮。**
配了 `health_keyword` 的会真搜一次并返回「搜索连通，返回 N 条资源」。
报「未配置 api_base」「未配置 search_path」这类，说明 `options` 没填对。

**第二步：去「站点健康」页。**
它比「测试」更狠：对搜索类站点真搜一次。三种状态：

| 状态 | 含义 | 处理 |
|---|---|---|
| 健康 healthy | 能连、有结果 | 完成 |
| 亚健康 degraded | 能连、**0 结果** | 九成是 Cookie 过期或字段映射错 |
| 故障 down | 连不上 | 检查地址、容器网络、代理 |

**第三步：搜一次，读「站点诊断」。**
搜索结果页会逐站给出诊断，这是判断「这个站为什么没出货」最直接的依据：

| 诊断 | 含义 | 怎么办 |
|---|---|---|
| `ok`，`raw` > 0 | 正常出货 | — |
| `empty` | 连通但没匹配 | 换关键词；或这个站本来就没这类资源（Nyaa 只收日番，搜中文剧名必然空） |
| `timeout` | 超时 | 调大 `CF_SEARCH_TIMEOUT`；站点太慢就禁用 |
| `error` + 4xx/5xx | 地址错、403 反爬、或对端服务没起 | 见 §5.1；`502` 常见于配了 Jackett 但没部署 |
| `ok` 但 `kept` 远小于 `raw` | 出货了但被筛掉 | 检查过滤规则组（体积/分辨率/关键词），以及去重 |

> `raw` = 站点原始返回条数，`kept` = 过滤去重后进入结果的条数。
> **两个数一起看**才能区分「站点没货」和「货被规则筛没了」——只看最终结果数会误判。

**第四步：如果只有某一个站出结果。**
先确认其他站是否 `enabled`。多站都启用了却只有一个出货，读它们各自的诊断状态；
v1.6.0 起结果合并已改为轮转交错（ADR-25），小站不会再被大站挤出结果窗口。

首次启动会**写入 20 条**示例站点（Jackett / Nyaa / Mukaku / 西瓜影院 /
Bilibili / YouTube / PanSou / KK 网盘搜 / 追剧 zhuiju.us / BT 世界网 /

> **为什么从 27 条降到 20 条**：v1.16.0 对每个内置站做了**逐站真实搜索**，

> 任何关键词都返回同一批结果），以及两个纯占位的 example.com 示例站
> （`/sites/presets` 里已有同样的模板，重复）。
> **判据是「详情页能否取到真链接」，而不是首页状态码 200**。

**默认启用的例外只有三类**（都不需要填任何配置）：

- `ytdlp`：本地库调用，装了依赖就能用；
- `kkso`（KK 网盘搜 / 追剧 zhuiju.us）：v1.14.0 从
  [awesome-zhuiju-free](https://github.com/laoma2053/awesome-zhuiju-free)
  清单里**实测筛出**的公开网盘搜索站，开箱即可搜到夸克/百度/迅雷链接；
- **磁力熊 Cilixiong**：v1.16.0 接入，地址与正则都已内置。
  ⚠️ 它的搜索**必须走 POST**（EmpireCMS）：用 `GET /?s=` 会**静默返回首页**，
  于是「任何关键词都有 20 条结果」，连乱码关键词也有——这种假成功比报错更难发现。
  正确配置见下方「POST 表单搜索」。

这份白名单在 `tests/test_api.py::DEFAULT_ENABLED_SITES` 里被强约束（**站点名**粒度，
因为同一个 `html_generic` 下既有开箱可用的磁力熊、也有要填地址的 BT 世界网）：
新加站点若手滑设成 `enabled=True`，测试会直接失败，避免用户一进来就看到一片报错。

### POST 表单搜索（`search_method: "POST"`）

搜索入口只认 POST 的站点这样配（以磁力熊为例）：

```json
{
  "search_url": "https://www.cilixiong.org/e/search/index.php",
  "search_method": "POST",
  "search_data": {"keyboard": "{keyword}", "classid": "1,2",
                  "show": "title", "tempid": "1"},
  "detail_link_field": "href=\"(/(?:movie|tv)/\\d+\\.html)\"",
  "max_detail_items": 6
}
```

`search_data` 里的 `{keyword}` / `{page}` 会被替换。怎么判断一个站要不要用 POST：
**用两个完全不同的关键词各搜一次，如果返回页面字节数一模一样，就说明抓的是首页**。

> **详情页标题**：`detail_link_field` 命中后会进详情页抓磁力，而详情页里的磁力
> 多数不带 `dn=` 参数。此时标题取自详情页的 `<h1>`/`<title>`
> （可用 `detail_title_field` 覆盖），**不再退化成搜索关键词**——
> 否则搜「流浪地球」会得到 20 条标题全叫「流浪地球」的结果，
> 既看不出清晰度/版本，本地关键词过滤也变成恒真。

## 8. 常见失败原因速查

| 现象 | 最可能的原因 |
|---|---|
| 测试报「未配置 api_base / search_path」 | `options` 是空的，或键名拼错 |
| 测试通过但搜索 0 条 | `list_path` 指错层级；或 `item_map.title`/`link` 映射错 |
| 有标题没链接 | 两阶段站点没配 `detail_extract`；或 `link` 字段名错 |
| 大小/做种数全是 0 | `size`/`seeders` 没映射，或站点返回的是带单位字符串（支持解析，但字段名要对） |
| 只出第一页 | `page_key` 没配；或 `page_base` 填成 0 而站点从 1 开始 |
| 私有站 0 结果 | Cookie 过期（见 §5） |
| 403 | 反爬（见 §5.1） |
| 502 / 连接被拒 | Docker 里写了 `127.0.0.1`，应写容器服务名（见 §1.2） |
| 站点很慢拖累整体搜索 | 单站超时由 `CF_SEARCH_TIMEOUT` 兜底，不会拖死整体；长期慢就禁用 |

## 9b. 社区清单（awesome-zhuiju-free）——一键添加实测可用的站

站点管理工具栏的 `🧭 社区清单` 接入了社区维护的追剧站点目录
[awesome-zhuiju-free](https://github.com/laoma2053/awesome-zhuiju-free)
（7.1k star，许可证 **CC-BY-4.0**）。和上面的「发现站点」不同，
这里的候选**已经被 CineFlow 真搜过一遍**。

### 操作步骤

1. **站点管理 → 🧭 社区清单**：打开即显示缓存的候选清单（首次会去拉一次上游）。
2. 点 **刷新清单** 可强制重新拉取（正常情况 12 小时自动更新一次）。
3. 点 **开始探测**：CineFlow 用「庆余年 / 凡人修仙传 / 流浪地球」逐站**真搜一次**。
   探测是串行且带间隔的，20 个站大约需要 **6~7 分钟**，可以关掉弹窗等它跑完。
4. 只有状态为 `✅ 可搜索` 的条目才有 **添加** 按钮。点一下即写入站点表。

### 四种探测状态的含义

| 状态 | 含义 | 能否添加 |
|---|---|---|
| `✅ 可搜索` | 真搜到了磁力 / 网盘 / 种子链接 | ✅ |
| `⚠️ 仅首页可达` | 站还活着，但搜索页给不出结果 | ❌ |
| `⛔ 被拦截` | 403 / 429 / 超时等 | ❌ |
| `· 未探测` | 还没测过 | ❌ |

### 为什么「仅首页可达」不给添加

上游的可用性检查是 `GET 首页` 看状态码。**首页 200 只说明域名还活着**，
和「搜得到东西」完全是两件事。实测数据：

| 判定来源 | 可用站数 |
|---|---|
| 上游 `reachable` | **14** |
| CineFlow 真搜一次 | **4** |

如果把那 12 个「仅首页可达」的站也加进来，你会得到 12 个看起来已启用、
但**每次搜索都只是白等一次超时**的站 —— 搜索会明显变慢，且没有任何收益。
这就是这里刻意做得「保守」的原因。想强行使用，仍可按前面的路径 C/D 手工添加。

### 它不会偷偷改你的站点表

定时任务 `zhuiju_sync`（设置页「社区站点清单」分组，默认 **1440 分钟**）
**只更新清单缓存与探测结论，绝不自动增删你的站点**。原因：上游删掉某个站时，
我们无法判断该不该删你的配置（你可能已经填了自己的 Cookie 或镜像地址）。
加不加站，永远是你点的那一下。

可调配置项：`ZHUIJU_SYNC_ENABLED`（总开关）、`ZHUIJU_SYNC_INTERVAL_MINUTES`、
`ZHUIJU_PROBE_ON_SYNC`（同步时是否顺带探测）、`ZHUIJU_PROBE_LIMIT`（单次探测上限）。

### 已经内置的成果

本轮从 20 个候选里筛出并直接内置为示例站点：

## 10. 不只是资源站：下载器 / 媒体服务器 / 通知渠道

这三类也统一走「站点管理」里的 Provider 配置，字段口径与资源站一致。

### 10.1 下载器

> ⚠️ v1.10.0 起，**下载器在「设置」页配置**（不在站点管理页），
> 那里会按下载器种类渲染出真实表单，不用手写 `options` JSON。

| Provider | 地址示例 | 备注 |
|---|---|---|
| `qbittorrent` | `http://qbittorrent:8080` | 填 WebUI 用户名密码，兼容 qB 5.x |
| `transmission` | `http://transmission:9091` | RPC，自动处理 409 令牌。**飞牛 fnOS / 群晖自带的下载器就是它** |
| `aria2` | `http://aria2:6800` | JSON-RPC，API Key 填 secret；直链下载走它 |
| `xunlei` | `http://192.168.1.10:5055` | 迅雷套件（**NAS 本地**）。不用填账号密码，但套件里必须先扫码登录你自己的迅雷账号 |
| `ytdlp` | 不填地址 | 本地进程，下 B 站/YouTube 等网页视频。登录用 `cookie_file` |

`options` 可设 `{"category": "CineFlow", "tags": "CineFlow"}` 便于在下载器里归类。

#### 飞牛 fnOS 用户怎么填

飞牛自带的下载器**就是 Transmission**，所以选 `transmission`、
地址填 `http://飞牛的IP:9091`（不是 6060）。若你在飞牛上另装了 qB 或迅雷套件，
就按对应 Provider 填。**不存在名为 `fnos` 的下载器**，
不用找（原因见 [ADR-52](04-决策记录.md)）。

#### 迅雷（NAS 本地）怎么填

1. 先在 NAS 的应用中心装好「迅雷」套件，打开它的页面**扫码登录自己的迅雷账号**。
   这一步必须手动做完 —— 没绑定账号时接口直接返回 500，CineFlow 会提示
   「迅雷套件未绑定账号」。
2. 地址填套件的访问地址（常见是 `http://NAS的IP:5055`，以你实际能打开的为准）。
   **用户名密码留空**：它的鉴权是套件自己发的本地令牌，我们自动从页面取。
3. 可选：`设备名称`（一个迅雷账号绑了多台 NAS 时用来指定，名称见迅雷 App）、
   `下载根目录名`（迅雷页面上的目录名，如「迅雷下载」，留空用第一个）。
4. 点「测试连接」。成功会显示「连接正常，设备已就绪」。

常见失败与含义：

| 提示 | 原因 |
|---|---|
| 迅雷套件未绑定账号 | 套件里还没扫码登录，去 NAS 上的迅雷页面登录 |
| 无法从迅雷套件页面取得本地鉴权 token | 地址不是迅雷套件（可能填成了 NAS 后台地址），或套件没启动 |
| 迅雷账号下没有绑定任何远程设备 | 账号登录了但这台 NAS 没被添加为远程设备，去迅雷 App 里确认 |
| 未找到名为 xxx 的迅雷设备 | `设备名称` 填错，留空可用第一台 |

**已知限制**：迅雷不支持暂停/恢复（本地 CGI 没有这个接口），
也不能指定任意保存路径 —— 只能落在它自己管理的下载目录下，
CineFlow 会用分类目录名（如 `movies`）在其中建子目录。
**不支持迅雷云端离线**，原因见 [ADR-51](04-决策记录.md)。

#### 下载器连不上时先看这三条

1. **地址一定要带 `http://`**。填 `192.168.1.5:8080` 会失败——
   v1.11.0 起会自动补全并去掉首尾空格，但升级前的版本会直接报连接失败。
2. **qB 留空账号密码不等于免密**。qB 默认只对**本机**免密，
   从 Docker 容器或别的机器访问仍需认证。要么填账号，
   要么在 qB 的「设置 → Web UI」里勾选对局域网免密。
3. **提示「403 被临时封禁」是登录失败次数过多**。等几分钟，
   或在 qB 的「Web UI」里调整封禁设置，别反复点测试。

#### 哪种资源需要哪个下载器（v1.13.0 起会主动提示）

下载器不是「装一个就够」——**每种资源只能交给收它的那种下载器**：

| 你要下的东西 | 必须装 | 装错的后果（v1.13.0 前会真的发生） |
|---|---|---|
| 磁力 / 种子 | qBittorrent、Transmission、aria2、迅雷 任一 | 只装 yt-dlp 时，磁力会被投给 yt-dlp 并**显示「正在下载」**，永远不会完成 |
| 网盘分享**留在云端** | 不需要下载器，配**网盘账号**即可（转存） | — |
| 网盘分享**下到本地** | **aria2** | 既没网盘账号又没 aria2 时，任务会一直 pending 且**界面上没有任何说明** |
| 直链 | aria2（或迅雷） | 同上 |
| B 站 / YouTube / 在线影视站 | **yt-dlp** | 投给 qB 会下到一个几 KB 的 **HTML 文件** |

v1.13.0 起这些都不用你记：**下不了的资源，下载按钮会置灰**，
鼠标悬停或点击会直接告诉你缺什么、去哪儿加，例如：

```
网盘资源下到本地需要 aria2：设置 → 下载器 → 添加 aria2；只想留在云端请用「转存」
```

想一次看全所有资源类型的当前状态，调 `GET /api/v1/downloads/routing`
（返回每类资源：可用的下载器有哪些、现在能不能下、不能下的原因）。

## 11. 网络视频下载（yt-dlp）

<!-- 这一节从 README 搬来：yt-dlp 的能力边界必须有唯一出处，避免两份文档各自漂移 -->

除了 BT / 网盘，还能把**公开的网页视频**收进媒体库（B 站 / YouTube / 抖音 /
TikTok / AcFun / 小红书等，抽取器覆盖 1700+ 站点，由 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 提供）。

下载页点「下载网络视频」，走**两步式**：先解析看清标题 / 作者 / 时长 / 可用画质，
确认无误再入队，避免下错东西浪费带宽。

```bash
# 解析（不下载）
curl -X POST "http://localhost:6060/api/v1/downloads/webvideo/probe?url=<视频页地址>" \
     -H "Authorization: Bearer <token>"

# 入队下载
curl -X POST "http://localhost:6060/api/v1/downloads/webvideo?url=<视频页地址>&max_height=1080" \
     -H "Authorization: Bearer <token>"
```

可配项（站点 `options`）：`max_height`（默认 1080）、`format`、`rate_limit`（KB/s）、
`write_subtitles` / `subtitle_langs`、`write_thumbnail`、`cookie_file`、`proxy`、`probe_retries`。
没装 ffmpeg 时自动退回单文件流（宁可画质低一档，也不要下到一半失败）。

**明确的边界**（详见 [ADR-24](04-决策记录.md)）：

- ✅ 只下**公开可访问**的内容：UP 主投稿、公开课、纪录片、自己发布的视频
- ❌ **不做** VIP / 付费内容解析。腾讯视频、爱奇艺、优酷、芒果 TV 的**正片播放页**
  以及 Netflix / Disney+ / Hulu / HBO / Prime Video 在**入口即被拒绝**，
  并提示改用平台官方客户端的离线缓存 —— 抓取这类内容等于绕过付费墙
- 需要登录才能看的内容，只支持你提供**自己账号**的 cookie 下载**你有权访问**的部分
- 默认带限速与并发上限，降低对站点的压力

站点会对连续解析做风控（B 站实测会回 `HTTP 412`）。因此解析结果**缓存 5 分钟**
（反复点「解析」瞬间返回），并对 412/429 做退避重试；
"视频不存在/已私有"这类确定性失败**不重试**，直接报原因。
