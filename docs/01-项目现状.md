# 01 · 项目现状

> 数据采集时间：2026-08-30 · 对应版本 **v1.12.0**

## 1. 一句话定位

CineFlow 是一个从零实现的 **NAS 影视自动化平台**：聚合 BT 站点与网盘搜索 →
自动追新 → 择优下载 → **自动转存网盘** → 规范命名入库 → 通知媒体服务器，
并支持在 **飞书 / 钉钉 / Telegram** 里用一句话发起搜索与下载。
v1.4.0 起还能**自动刮削 NFO**、把网盘目录映射成 **STRM** 直接播放、
**追更网盘分享链接**里的新集，并在出现更优画质时**洗版**替换已入库文件。
v1.5.0 补上了**运维与治理**能力：52 项配置可在线改、三档用户权限、
站点健康巡检（抓 Cookie 静默失效）、多下载器负载均衡与失败换源、
榜单自动订阅、以及能表达「宁可 1080p 中字也不要无字幕 4K」的**过滤规则组**。
v1.6.0 面向"看得见、搜得全"：搜索会报出**每个站点的成败原因**且小站不再被大站挤掉、
热榜改为带真实封面的**画板**（不依赖 TMDB）、并能下载 B 站/YouTube/抖音/TikTok 等
**公开**网页视频（明确不做 VIP 正片解析，见 ADR-24）。
v1.7.0 面向"管得住、认得出"：网盘从"只能浏览+转存"补齐为**完整文件管理**
（改名/移动/复制/盘内搜索，按后端**能力位**渲染）并新增 **6 小时凭据保活**；
封面接入**豆瓣**（免 API Key）作为回退，并用后端图片代理解决豆瓣图床的 418；
B 站与 YouTube **并入聚合搜索**（破 412 风控）；网盘类资源现在同时提供「转存」与「下载」。
设计上参考 [MoviePilot](https://github.com/jxxghp/MoviePilot) 的订阅/插件体系与
[T3FAP](https://github.com/qq85423296/T3FAP) 的网盘资源思路，代码与数据模型完全独立编写。

## 3. 已实现能力

### 搜索与择优
- 多级关键词（`片名 S02E05` → `片名 S02` → `片名`）并发查询所有站点
- BT + 网盘双通道；跨站按 infohash 去重
- 硬过滤（枪版/无关剧/做种不足）+ 加权打分（4K>1080p、中字 +30、季包 +25）

### 自定义站点接入（无需写代码）
- `api_generic`：JSON API 字段映射，支持两阶段详情抓取
- `html_generic`：正则解析网页
- `mukaku`：内置预设，开箱可用（`https://web5.mukaku.com`）
- 从导航站发现候选站点（`/sites/discover`）
- 13 条默认示例站点；需填地址/账号的**默认禁用**，`ytdlp`（本地库调用）默认启用；升级时按名字**补齐而不覆盖**（ADR-06）

### 自动追新（两条互补链路）
| | 订阅巡检 | 追新雷达 |
|---|---|---|
| 驱动 | 逐订阅去各站搜索 | 拉各站最新流再匹配订阅 |
| 请求量 | 订阅数 × 站点数 | 站点数 |
| 默认间隔 | 30 分钟 | 15 分钟 |

缺集判断双来源（DB `downloaded_episodes` ∪ 媒体库实际文件），永不重复下载。

### 网盘管理（v1.3.0 新增，v1.4.0 增 WebDAV）
- 4 种存储：`alist`（推荐网关，一套接 20+ 盘）、`quark`（直连样板，
  完整四步转存 + 分享列举）、**`webdav`**（一份实现覆盖 Nextcloud / 坚果云 /
  群晖 / TeraCLOUD / AList DAV，明确不支持分享转存）、
  `local_dir`（本地/挂载目录，零配置试用 + 路径越界防护）
- 容量、面包屑目录浏览、建目录、删除、临时直链
- **自动转存**：网盘资源命中后直接转存（`CF_PAN_AUTO_SAVE`），
  失败留在待转存队列由 `cineflow.pan_transfer` 定时重试（ADR-09）
- 转存记录表（`pan_saves`）可回溯每次成功与失败原因
- 10 个 API + 「网盘管理」页

### ChatOps 机器人（v1.3.0 新增）
- 三平台：飞书（v1/v2 token + URL 挑战 + AES 加密推送）、
  钉钉（HMAC-SHA256 时间戳签名 + 防重放）、Telegram（secret token）
- **42 个别名 → 8 个规范指令**：搜索/下载/订阅/订阅列表/状态/转存/热榜/帮助
- 会话上下文：`搜索` 后回 `下载 2` 即可，按平台+会话+用户隔离，900 秒过期
- 幂等去重（10 分钟）、用户白名单、指令审计
- ⚠️ **未配验签密钥默认拒绝**（ADR-04，相对更早版本是破坏性变更）

### 入库与通知
- 5 种转移模式：`link` `copy` `move` `softlink` `strm`
- 规范命名模板；字幕跟随；跨盘自动降级
- 通知 Emby/Jellyfin/Plex 刷新；Telegram/企微/Bark/Webhook 推送

### 热度排行（v1.2.0）
四张榜单：资源热榜 / 实时热榜 / 搜索热词 / 站点贡献榜。
热度为可解释加权分，并做了**去碎片化归并**（剥离版本/集号/季号标记）；
无法判定类型的条目折叠进「全部」而不单开 tab（ADR-07）。

### NFO 刮削与分类归档（v1.4.0 新增）
- `core/nfo.py` 纯渲染（可离线单测，无 IO）：`movie` / `tvshow` / `season` /
  `episodedetails` 四种根节点 + `poster` / `fanart` 命名惯例
- `services/scraper.py` 才做 IO：入库即刮、`媒体库补刮` 定时任务补历史文件、
  媒体库页手动 `补刮 NFO`；TMDB 不可用时降级写最小 NFO（标记 `degraded`）
- 默认**不覆盖**已有 NFO（`CF_SCRAPE_OVERWRITE=false`），不冲掉用户手改
- `core/categories.py` 判 电影 / 电视剧 / 动漫 / 纪录片 / 综艺 / 儿童 六类，
  TMDB genre 优先、关键词兜底；**判不出返回 `None` 不归档**，默认关闭（ADR-13）

### STRM 同步 + 302 播放（v1.4.0 新增）
- 网盘目录 → 本地 `.strm`；Emby/Jellyfin 扫到即当成一集
- 两种链接模式：`proxy`（默认，写 `/api/v1/strm/play/{id}`，**链接永不过期**，
  该端点匿名且只回 302 不代理流量）/ `direct`（写临时直链，NAS 零参与但会过期）
- 源文件消失时清理失效 `.strm`，避免"幽灵剧集"；字幕/NFO/图片等随行文件本地化

### 网盘分享追更（v1.4.0 新增）
- 给分享链接即可追日更剧：按文件名**增量**转存新集，不重复搬
- 包含/排除关键词 + 正则过滤（用户写错正则按没填处理，不搞崩巡检）
- 重命名规则可把 `第08集.mp4` 落成 `剧名 - S01E08.mp4`
- 限定星期几 / 到期时间控制节奏；连续失败到阈值标记 `invalid` 停手
- 不支持增量列举的网盘用哨兵记录防止反复整体转存

### 洗版（v1.4.0 新增，默认关闭）
- 仅对勾选 `best_version` 的订阅生效；评分差 ≥ `CF_UPGRADE_SCORE_DELTA`（15）才替换
- 每文件最多洗 `CF_UPGRADE_MAX_TIMES`（2）次，防止在同档版本间反复横跳
- **先入库再删旧**（`library.replace_library_file`），中途失败不留空洞
- 订阅页提供「洗版试算」只报告不执行

### 定时任务可视化（v1.2.0 起，v1.12.0 为 14 个）
14 个内置任务可在界面改 interval/cron、立即运行、暂停/恢复，写入 `settings` 表：
`subscribe` `radar` `download` `pan_transfer` `pan_subscribe` `pan_keepalive` `strm_sync`
**`video_subscribe`** **`speed_limit`** **`site_health`** **`ranking`** `scrape` `upgrade` `library`。

### 设置页（15 组，其中 52 项可在线改）
15 个分组，**52 项支持在线修改且立即生效**（v1.6.0 新增 `SEARCH_MAX_PER_SITE`；按类型渲染控件、只提交改过的项、
一项非法整体拒绝、可单项/全部恢复默认）；目录/端口/密钥等启动期配置保留只读
并标「需重启」。敏感项脱敏为 `******（已设置）`；同页提供改密与通知测试。
这是对 ADR-05 的修正：不是全放开，而是**只放开真能生效的**（ADR-18）。

### 多用户与权限（v1.5.0 新增）
- 三档角色：`admin`（全部）/ `operator`（搜索订阅下载入库，改不了配置与用户）/
  `viewer`（只读）
- 前端按角色隐藏入口，但**服务端逐端点校验**——界面隐藏不是安全边界
- 鉴权读数据库角色而非 JWT 副本：改完角色立即生效
- 自我保护：不能删/停用自己，最后一个启用中的管理员不能被降级或停用

### 站点健康巡检（v1.5.0 新增）
- 对搜索类站点**真搜一次**（不是只探首页），三档判定：
  `ok` / `degraded`（能连通但 0 结果或极慢）/ `down`
- **0 结果算降级**：Cookie 过期时首页照样能开，只有搜索结果归零——
  这是最难发现的故障（ADR-20）
- 连续失败达阈值才告警，且只在状态翻转时通知；手动探测不发通知
- 每站留 50 条历史；可选连续失败自动停用站点（默认关闭）

### 下载器负载均衡（v1.5.0 新增）
- 三策略：`priority`（默认，同旧行为）/ `least_tasks` / `round_robin`
- 不健康的下载器**排后而不剔除**（健康数据可能过期，ADR-21）
- 投递失败自动换下一个候选下载器

### 榜单自动订阅（v1.5.0 新增）
- 4 个来源：TMDB 趋势/热门/高分 + **本地资源热度榜（无需 TMDB Key）**
- 条件：媒体类型、取前 N、最低评分/票数、最早年份、标题包含/排除
- **单次有上限**（默认 5）且记 `handled_ids`：手动删掉的订阅不会被加回来（ADR-23）
- 支持 `dry_run` 试算

### 自定义过滤规则组（v1.5.0 新增）
- **有序分层**而非调权重：命中靠前层的整体优于靠后层，层内仍按既有评分排序
- 这样才能表达「宁可 1080p 中字，也不要没字幕的 4K」——全局评分做不到（ADR-22）
- 每层条件全部可留空 = 不限制；可绑定到单个订阅，也可设全局默认组
- 内置 4 模板（画质优先/均衡/省空间/动漫），**全部不设为默认**，避免悄悄改排序
- 「试算」可拿样例资源当场看分层结果

### 界面
22 个功能页、暗色/浅色/跟随系统三档主题、token 化设计系统、约 39 个内联 SVG 图标，
**零依赖**（无 CDN、无构建工具，ADR-08）。

### 热度排行画板（v1.6.0 新增）

资源热榜与实时热榜默认以卡片墙展示，可切回列表。封面/评分/年份/类型/演员
**取自站点搜索接口自带的元数据**，不依赖 TMDB（ADR-26）；
站点没提供时降级为按标题哈希取色的占位块，而不是裂图或留白。
纯盘搜类站点（PanSou）本身无元数据源 —— v1.7.0 起这类条目会由**豆瓣**兜底补图
（见下），仍拿不到时才显示占位。

### 搜索每站诊断（v1.6.0 新增）

搜索响应带 `sites[]`，逐站给出 `ok | empty | timeout | error`、原始/保留条数、
耗时与失败原因。聚合时按站点**轮转交错**合并，小站不再被大站挤出结果窗口（ADR-25）。

### 网页视频下载（v1.6.0 新增）

`ytdlp` Provider 覆盖 1700+ 站点（B 站/YouTube/抖音/TikTok…）。
两步式：先解析看清标题/作者/时长/画质，确认再入队。
**只下公开内容**：长视频平台正片播放页与 Netflix/Disney+ 等在入口即拒绝（ADR-24）。

### 网盘完整文件管理与保活（v1.7.0 新增）

网盘页除浏览/转存/删除外，新增**改名 / 移动 / 复制 / 盘内搜索 / 新建目录**。
按钮**按后端下发的能力位渲染**：`GET /api/v1/pan` 返回每个存储的 `capabilities`，
不支持的操作根本不显示，而不是点了才报错（ADR-28）。

|---|---|---|---|---|---|---|
| `quark` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `pan115` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `alist` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `webdav` | ✅ | ✅ | ✅ | ✅ | ❌ 协议无搜索语义 | — |

既刷新登录态又能在失效时**提前告警**，而不是等半夜转存任务失败（ADR-33）。

### 豆瓣封面兜底与图片代理（v1.7.0 新增）

封面回退链：**站点自带 → 豆瓣 → TMDB（需 Key）→ 占位色块**。
豆瓣走公开的 `subject_suggest`（**无需 API Key**，中文命中率高于 TMDB），
自带缓存 6h + 命中限流退避 300s（ADR-29）。
豆瓣图床校验 `Referer`（裸请求 418），而浏览器跨站会剥离 Referer、前端无解，
故由后端 `/api/v1/images` 代理补 Referer 转发；
代理有 **SSRF 三道防线**：域名白名单（精确后缀比较）、仅 http(s)、
响应必须 `image/*`（ADR-30）。

### B 站 / YouTube 并入聚合搜索（v1.7.0 新增）

启用 `bilibili` / `youtube` 站点后，它们与 BT 站、盘搜并发搜索。
B 站搜索接口对无 `buvid3` Cookie 的请求返 412，故**先预热首页拿 Cookie**（ADR-31）；
YouTube 复用 yt-dlp 的 `ytsearch{N}:` + `extract_flat`，不自研解析。
播放量**投影到 `seeders`**，无需给榜单排序加特例（ADR-32）。

### 发现榜：豆瓣四分类 + Bilibili（v1.8.0 新增）

与既有的「热度排行」**并存而非替换**——两者口径不同（ADR-36）：
`/trending` 说的是「我的站点上什么资源最好下」，
`/trending/discover` 说的是「外面现在什么剧火」（可能一条片源都没有）。

| 分类 | 来源 | 实现要点 |
|---|---|---|
| 电影 | 豆瓣 `type=movie` | `search_subjects` 公开接口，需带 `Referer` |
| 电视剧 | 豆瓣 `type=tv&tag=国产剧` | 豆瓣的 `type` **只有 movie/tv**，其余靠 tag 区分 |
| 动漫 | 豆瓣 `type=tv&tag=日本动画` | 实测 `tag=动画` 返回 **0 条**，必须用「日本动画」 |
| 综艺 | 豆瓣 `type=tv&tag=综艺` | — |
| Bilibili | B 站排行榜，8 个二级分区 | UGC 走 `ranking/v2`，**PGC（番剧/国创）走 `pgc/season/rank`**（ADR-37） |

两条实测踩坑：B 站裸请求返 `code=-352`（风控）→ 沿用 ADR-31 先预热首页拿 `buvid3`；
`rid=13`/`rid=167` 在 `ranking/v2` 返 `-400`，因为它们是 PGC 内容，接口不同。

每个榜单条目会标注**「你的站点已有 N 条片源」**——这是发现榜相对纯榜单站的价值：
同时给出「外部热度」与「本地可得性」。
缓存：豆瓣 1800s / B 站 900s，限流退避 300s，异常一律降级空列表不 500。

### 网盘账号登录：扫码 + Cookie 导入（v1.8.0 新增）

补上了 T3FAP 做得比本项目好的一环——不再要求用户手动 F12 抠 Cookie。

| 网盘 | 扫码 | Cookie 导入 | 实测结论 |
|---|---|---|---|
| `pan115` | ✅ | ✅ | 官方 `qrcodeapi.115.com` 全链路跑通（申请 uid → 二维码 PNG → 长轮询 → `passportapi` 换 Cookie） |
| `baidu` | ⚠️ | ✅ | passport 扫码可用；风控可能要求二次验证，失败时引导改用 Cookie |
| `quark` | ❌ | ✅ + 即时校验 | 登录需签名公参（`x-pan-client-id`/`x-pan-tm`/`x-pan-token`），逆向属对抗风控，**明确不做**（ADR-38） |

安全约束（四条，均有回归测试）：

1. 扫码会话**只存进程内存**，TTL 600s，不落库不写日志（ADR-39）
2. 会话唯一对外序列化出口 `to_dict()` **不含 cookie 字段**
3. **校验不通过一律不写库**（ADR-40）——否则错误会被推迟到半夜定时任务失败时才暴露
4. 对外 Cookie 导入接口**不提供 `verify=false` 开关**（本轮冒烟测试抓到的真实漏洞：
   带上它可把任意字符串写成 Cookie 并启用站点，等于绕过第 3 条）

前端不写死能力差异，读后端 `PROVIDERS` 声明的 `qrcode` 位渲染（沿用 ADR-28）。

### 新番放送日历（v1.12.0 新增）

榜单第七个页签「新番」，另带**第三种视图**（画板 / 列表 / **日历**）。
数据源是 Bangumi（bgm.tv）公开 `/calendar`，**免 API Key**，实测一周 **113 部**在播动画。

为什么不用已有的「动漫」页签：那是豆瓣热度榜，回答「大家在看什么」；
追番要的是「这周哪天更新第几话」——**热度榜的排序维度里没有时间**，答不了（ADR-56）。

三个实测坑（都会让界面「看起来正常」却是错的）：

| 坑 | 表现 | 处理 |
|---|---|---|
| `weekday.id` 是 **1~7**（周一起），Python `weekday()` 是 **0~6** | 日历整体错开一天，界面上完全看不出 | 显式映射，测试钉住 1~7 全部取值 |
| 封面 **113/113 全是 `http://`** | HTTPS 部署下被混合内容策略拦掉，条目在但全是空白块 | 统一改写 `https://`，`bgm.tv` 加进图片代理白名单 |
| 约 **10%** 条目 `name_cn` 是空串 | 出现一批无名条目 | 回退日文原名 |

Bangumi **不计入 Provider 数**（仍 29 个）——它是元数据源（同豆瓣），
不是可搜索/可下载的站点。

### UP 主 / 频道视频追更（v1.12.0 新增）

第 22 个功能页「视频追更」。填一个 B 站空间或 YouTube 频道地址，
每 **120 分钟**检查一次，有新视频就自动入队下载。

与既有订阅的区别：`Subscribe` 以「作品 + 季 + 集」为主键，UP 主没有季集概念，
所以新建 `VideoSubscribe` 表（第 20 张）而不是硬塞进去。

**核心设计是「增量判据用视频 ID」**（ADR-58）。原因是 B 站 space API 实测返 **412**
（要 wbi 签名，属对抗风控，不做 → 改用 yt-dlp `extract_flat`，ADR-57），
而扁平提取下 B 站**不给标题也不给日期**，只有 ID 稳定。由此派生三条必须的配套：

| 设计 | 不这么做的后果 |
|---|---|
| 标题缺失时 include/exclude **放行** | 拿正则匹配 `None` → **永远一个都下不到**，且没有任何报错 |
| 首检 `skip_existing` **只记账不下载** | 一订阅就被灌进几百个历史视频 |
| 下载失败**也写入** `handled_ids` | 每轮重试同一个坏链接，把 `max_per_run` 额度占满，新视频永远排不上 |

另有：`handled_ids` 只留最近 500 条（防 JSON 无限膨胀）；
连续 5 次失败自动 `paused`（防已注销账号让任务白跑），`reset_failures` 手动恢复。

### 下载器限速时段（v1.12.0 新增）

设置页「下载器限速时段」卡片：白天限速、夜间放开、其余时段用默认值，
每 **10 分钟**幂等下发到所有支持的下载器。

这里推翻了 v1.11.0 的一个判断（原写「限速该在 qB 自己界面里做」）：
限速是**按时间变化的**，而挂了三个下载器就得进三个 WebUI 配三遍，
三家的单位和开关语义还都不一样。这正是聚合层该做的事（见 `docs/09` §10.3）。

**三个下载器三种错法**，且写错的表现都是「配了没生效」而不是报错：

| 下载器 | 正确做法 | 写错的后果 |
|---|---|---|
| qBittorrent | API 收 **B/s**，配置填 KB/s，**必须 ×1024** | 差 1024 倍，等于没限速 |
| Transmission | 收 **KB/s 不乘**，但**必须同时下发 `speed-limit-*-enabled`** | 值存了，下载照样满速 |
| Transmission（填 0） | **关开关**，不是限速到 0 | 0 KB/s 是真的 0，彻底断流 |
| aria2 | 值**必须是字符串** `"5120K"` | 传数字被直接拒绝 |

**跨午夜**（`23:00-07:00`）用朴素 `start <= now <= end` 比较**恒为假**，
夜间时段永远不生效而白天看起来一切正常；已显式拆两段判断，`start == end` = 全天。
`xunlei` / `ytdlp` 继承基类 `supports_speed_limit = False`，如实返回 `skipped`——
**伪造成功比不支持更糟**。刻意不做单任务限速（ADR-60）。

### 通知按事件分渠道 + 告警去抖（v1.12.0 新增）

每个通知渠道可配 `events` 白名单 / `events_exclude` 黑名单 / `min_level` 等级门槛，
白黑名单都支持 `download.*` 前缀通配。终于能表达「只把失败推到手机、日报走邮件」。

**不配置就是全收**（ADR-59）：老配置里没有这些字段的渠道行为**完全不变**。
反过来做（默认不收）的后果是升级即静默失联——所有通知消失且没有任何报错。
同理，白名单模式下**调用方没传 `event` 也放行**，否则老调用点的通知会被静默吞掉。

去抖：`NOTIFY_ALERT_COOLDOWN_MINUTES`（默认 360 分钟）按 key 独立计时，
恢复正常时立刻解除，不压制「恢复通知」。

> 🔴 做这件事时发现一个真缺陷：`pan_storage.keep_alive_all()` 的 docstring
> 明写「凭据失效走通知」，但**代码里从来没有发过通知**——保活任务每 6 小时
> 发现 Cookie 挂了只改了个状态位，用户只能自己去页面看。已补齐。

### 封面匹配置信度：宁可空白也不给错封面（v1.12.0 新增）

`match()` 新增 `MIN_MATCH_SCORE = 60` 门槛与 `match_score` / `match_confidence` 返回值，
年份不符罚 60 分、差 1 年罚 15 分。原则是**空白封面是可见的缺失，错封面是看不见的错误**。

这条改动最有价值的部分是**写测试时反向抓出的两个既存错误**（ADR-61）：

1. **`sub_title == title` 时重复加分，把年份罚分整体架空**。实测中文条目
   （庆余年 / 流浪地球 / 三体）`sub_title` 与 `title` **完全相同**，
   于是「别名命中 +20」白送给每个中文条目，同名不同年算下来
   `100+20+5-60 = 65` **越过 60 门槛**——年份校验写了却等于没写。
2. 修完第 1 条，`庆余年` 反而配不上 `庆余年 第一季`。豆瓣分季命名极普遍
   （`西部世界 第一季` / `凡人修仙传 年番4` / `流浪地球2`），纯字面包含 50 分不够。
   新增 `_SEASON_SUFFIX_RE` + `_is_season_suffix()` 给季号后缀 60 分，
   同时不放过 `三国` → `三国演义` 这种真不匹配。

9 个真实条目实测：庆余年 65 / 凡人 105 / 流浪地球 135 / 西部世界 95 /
无间道(2002) 135 / 三国 → `None`。

## 6. 已知限制（设计取舍，非缺陷）

- **导航站不提供资源**：`mukaku` 等站点自身是资源站；导航站（如影盒指南）
  只用于**发现**候选站点，不产出磁力链
- `mukaku` 搜索需用**中文片名**（站点索引特性）
- 未配 TMDB 时全量降级：识别仍可用（走本地正则解析），只是没有海报与元数据
- 网盘资源默认不进 BT 下载器；直链需 aria2
- AList 转存走**异步离线下载**，接口成功仅代表「已提交」，非「已落盘」
- 夸克直连依赖 Cookie，**会过期**；v1.7.0 的保活能延长有效期并提前告警，
  但**不能保证永不掉线**，彻底失效仍需人工更新
- 豆瓣 `subject_suggest` 是**按标题模糊匹配**；v1.12.0 已加年份校验与 60 分门槛，
  低于门槛**返回空而不是给错封面**（M41 / ADR-61）。代价是少数冷门条目会没封面
- 图片代理**不校验登录**（`<img>` 带不了 `Authorization`），
  安全性由域名白名单保证；自行加白名单前须确认域名不指向内网
