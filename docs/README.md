## 文档维护约定

1. **只写经过验证的事实**。数量、端点数、表数等必须与代码一致，
   由 `scripts/verify_docs.py` 自动校验（CI 门禁）。
   文档过期会**导致门禁失败**——这是刻意设计，不要靠人记得。
2. **路线图状态必须及时更新**：`规划中` / `进行中` / `已完成` / `已放弃`，
   已完成项要写清「验收证据」（哪个脚本/测试/命令证明它可用）。
3. **决策要留痕**：推翻旧设计时不要删除原 ADR，追加一条新 ADR 说明原因，
   并在旧条目标注「已被 ADR-xx 取代」。
4. **面向 review**：每个升级步骤都要能回答三个问题——
   改了什么、为什么这么改、怎么证明它是对的。
5. **破坏性变更必须在变更日志里单独标注 ⚠️**，并写明升级动作。
