# 精简优化与升级说明

本轮保留影视自动化、网盘、视频追更、ChatOps 与插件能力。界面侧栏为总览及六个主流程入口，原有页面移入相关流程的次级导航，旧 hash 链接继续有效。

## 升级前

停止应用并备份数据目录中的 SQLite 数据库、配置与 STRM 输出目录，再使用新代码或重新构建镜像。数据库初始化会幂等补充播放凭据与自动投递键，已有下载任务不被批量删除。

## STRM 播放链接

旧的无凭据 `/api/v1/strm/play/{记录ID}` 不再换取直链。升级后进入“网盘管理 → STRM 同步”，点击“重写播放链接”。此操作根据已有索引重写本地 proxy STRM，无需扫描或下载网盘视频。

如需吊销曾分享过的链接，点击“轮换播放凭据”。这会更新 STRM 中的随机凭据，旧链接立即失效；播放器可能需要重新加载文件。普通重写与日常同步保留已有凭据。direct 模式保留网盘临时直链语义。

STRM 清理只覆盖本次源目录及输出范围。目录请求失败、过深、分页未读全或预算截断时跳过推断性删除；完整扫描得到空目录时可清理该范围内的失效 STRM，不删除远端视频。

## 调度与任务

设置页的周期项引导至“订阅追新 → 定时任务”。旧设置 API 仍兼容，但实际只保存到 `schedules`。升级前存在两套值时保留原本执行的调度值，冲突旧值归档到 `legacy_schedule_config`。

自动下载在访问下载器前先占位。进程中断后无法证明外部下载器是否已接受时，保留“投递待确认”状态，不自动重复投递。核对外部下载器后，可移除该任务占位再重试。明确失败或取消的任务仍可重试，手动重复下载继续允许。

洗版先验证新文件可用，合并新旧索引后保留质量与洗版次数；旧文件删除失败时保留索引、任务错误与重试目标，后续同步继续收尾。

## 开发与回滚

运行依赖由 `requirements.lock` 固定，开发与 CI 使用 `requirements-dev.lock`，支持 Python 3.10 / 3.12。镜像构建在测试及静态检查通过后进行。本轮不会自动推送或发布镜像。

回滚时停止应用，恢复升级前的数据库、配置与 STRM 备份，再切回原代码/镜像。只切代码不能恢复已轮换的播放链接或旧配置优先级。

数量统计见 [项目事实](project-facts.md)，验证方法见 [开发指南](14-开发指南.md)。
