# 06 · 网盘管理

> 让网盘资源**自己转存进自己的盘**，而不是提醒你去手动点一遍。

---

## 1. 先分清两件事：盘搜 vs 网盘存储

CineFlow 里有两类都叫「网盘」的东西，**职责完全不同**，配置也是两条记录：

| | 盘搜（搜索器） | 网盘存储（存储器） |
|---|---|---|
| 代码目录 | `app/providers/pan/` | `app/providers/panstorage/` |
| 抽象基类 | `SearchProvider` | `BasePanStorage` |
| `kind` | `pan` | `panstorage` |
| 做什么 | 在第三方索引里**找到别人的分享链接** | 把链接**转存进你自己的网盘**、浏览你的目录 |
| 读写 | 只读、可随意并发 | 可写（会真的建目录/删文件） |
| 实现 | `pansou` `pan_generic` | `alist` `quark` `webdav` `local_dir` |

典型链路：**盘搜找到分享链接 → 存储器转存到自己盘 → 入库/STRM**。

> 为什么要拆成两类，见 [`04-决策记录.md`](04-决策记录.md) ADR-01。

---

## 2. 四种存储的配置

在「站点管理」里添加 `kind=panstorage` 的站点，或直接启用系统预置的 3 条示例
（`DEFAULT_SITES` 里已含，**默认全部禁用**，改完配置再启用）。

### 2.1 AList 网关（推荐）

| 字段 | 位置 | 说明 |
|---|---|---|
| `url` | 站点 URL | AList 地址，如 `http://127.0.0.1:5244` |
| `username` / `password` | 站点凭据 | 走 `/api/auth/login` 换 token |
| `api_key` | options | 也可直接填 AList 的固定令牌，免登录 |
| `root_path` | options | 转存落地目录，默认 `/` |
| `offline_tool` | options | 离线下载工具，默认 `SimpleHttp` |

**为什么推荐**：一套 AList 后面能挂 20+ 家网盘，CineFlow 不必逐家逆向私有协议
（ADR-02）。

### 2.2 夸克网盘（直连样板）

| 字段 | 位置 | 说明 |
|---|---|---|
| `cookie` | options | 浏览器里复制的**完整 Cookie**，必填 |
| `root_path` | options | 转存落地目录 |

⚠️ **Cookie 会过期**，这是直连方案的固有代价。过期后健康检查会失败，
界面提示重填即可；不要当成 bug。

### 2.3 WebDAV（一份实现接一堆网盘）

| 字段 | 位置 | 说明 |
|---|---|---|
| 站点 URL | url | WebDAV 根地址，如 `https://dav.jianguoyun.com/dav/` |
| `username` / `password` | options | Basic Auth 账号密码（坚果云用「应用密码」） |
| `base_dir` | options | 可选，把操作限定在某个子目录 |

覆盖面：**Nextcloud / 坚果云 / 群晖 Synology Drive / TeraCLOUD / AList 自带 DAV**。
选它而不是逐家写私有 API 的理由见 ADR-02——一份标准协议实现，
不用跟着各家接口变更打补丁。

实现要点：
- `PROPFIND`（`Depth: 1`）列目录并解析 XML；`MKCOL` 建目录；`PUT`/`DELETE` 读写
- 容量取 `quota-available-bytes` / `quota-used-bytes`，服务端不给就显示未知
- 路径统一做 percent 编码，**中文与带空格的目录不会 404**
- 提供 `auth_header()`，可供 STRM 302 播放复用鉴权

⚠️ **明确不支持「转存别人的分享链接」**（`supports_save = False`）：
WebDAV 协议里没有这个语义。调用转存会返回明确提示而不是假装成功。
需要转存分享请用 AList（离线下载）或夸克直连。

### 2.4 本地/挂载目录（零配置试用）

| 字段 | 位置 | 说明 |
|---|---|---|
| `base_dir`（或站点 URL 填 `file:///D:/pan`） | options | 要当成网盘浏览的本地目录 |

用途：把 rclone / CloudDrive / CloudNAS 挂载出来的目录当网盘浏览，
**完全不联网**就能验证目录浏览、容量、建目录、删除是否正常，
适合先跑通流程再接真网盘。

**安全约束**：所有路径都会 `resolve()` 后校验是否仍在 `base_dir` 之内，
`../` 越界会被拒绝（有专门单测）。若 `base_dir` 未配置，返回 `None`
并给出「未配置 base_dir」提示——**绝不会**退化成把进程当前目录当网盘。

## 3. 转存是怎么做的

### 3.1 夸克四步流程

```
1. POST /share/sharepage/token    分享码(+提取码) → stoken
2. POST /share/sharepage/detail   列出分享内文件 → fid / share_fid_token
3. POST /share/sharepage/save     提交转存任务   → task_id
4. GET  任务轮询                   task_id → 成功/失败（默认重试 10 次）
```

每步失败都有明确文案，便于用户自查：

| 失败点 | 提示 |
|---|---|
| 链接格式不对 | 不是有效的夸克分享链接 |
| 第 1 步 | 获取分享 token 失败（链接失效或提取码错误） |
| 第 2 步 | 分享内没有可转存的文件 |
| 第 3 步 | 提交转存失败（可能容量不足或文件已存在） |

### 3.2 AList 离线下载

调 `POST /api/fs/add_offline_download`，把链接交给 AList 挂载的网盘去拉。
提取码按 AList 约定拼进链接：

```
https://pan.xxx.com/s/abcd  +  提取码 1234
→ https://pan.xxx.com/s/abcd?pwd=1234
```

⚠️ 这是**异步提交**：接口返回成功只代表「已提交」，不代表已落盘。
所以 `SaveResult.message` 写的是「已提交 AList 离线转存（工具：SimpleHttp）」。
是否真的下完，去 AList 的任务列表看。

### 3.3 挑哪个盘转存

`_pick_for_share()` 的策略：**同家优先**。

```
pan.quark.cn 的分享  → 优先给 quark
alipan/aliyundrive  → 优先给 alipan
pan.baidu.com       → 优先给 baidu
115.com / 115cdn    → 优先给 115
pan.xunlei.com      → 优先给 xunlei
都不匹配             → 退回第一个支持转存的盘（通常是 AList 离线下载）
```

同家转存是「秒传级」的服务端操作，最可靠；跨家只能靠离线下载中转。

## 4. 自动转存链路

```
订阅巡检/雷达命中网盘资源
      ↓
download.add_download()  ← kind=pan
      ↓  CF_PAN_AUTO_SAVE=true（默认）
pan_storage.save_share()  立即尝试转存
      ├─ 成功 → 任务置 TRANSFERRED，progress=1.0，meta 记 storage/saved_path
      └─ 失败 → 任务留在 PENDING，error 记原因
                     ↓
        定时任务 cineflow.pan_transfer（默认每 20 分钟）
        批量重试所有 PENDING 的 pan 任务
```

- `CF_PAN_AUTO_SAVE=false` 时只登记不转存，全部交给定时任务或手动按钮。
- `CF_PAN_TRANSFER_INTERVAL_MINUTES` 控制巡检间隔（默认 20）。
- `CF_PAN_TRANSFER_BATCH` 控制单轮最多处理条数（默认 20），避免一次打爆网盘接口。
- 转存失败**不会**让 `add_download` 整体失败（ADR-09），因为订阅是无人值守跑的，
  失败即丢会变成「明明搜到了却什么都没发生」。

## 5. 待转存队列与转存记录

### 待转存队列
`GET /api/pan/pending` 列出所有 `kind=pan & status=pending` 的任务。
网盘管理页顶部显示条数，提供：

- **一键全部转存** → `POST /api/pan/transfer`
- **单条转存** → `POST /api/pan/save`

⚠️ 手动按钮和定时任务走的是**同一个** `pan_storage.transfer_pending()`，
不存在两套逻辑，行为完全一致。

### 转存记录
`GET /api/pan/records` 读 `pan_saves` 表，每次转存（成功与失败）都留一行：

| 字段 | 用途 |
|---|---|
| `storage` | 转到了哪个盘 |
| `share_url` / `password` | 原始分享与提取码 |
| `saved_path` / `file_count` | 落在哪、几个文件 |
| `success` / `message` | 失败原因原文 |

排障时先看这张表：能立刻区分「压根没触发转存」和「触发了但被网盘拒绝」。

## 6. API 一览（14 个 + 分享追更 5 个）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/pan` | 总览：每个盘的容量与能力 |
| GET | `/api/pan/files?site_id=&path=` | 浏览目录（返回 `parent` 供面包屑） |
| GET | `/api/pan/pending` | 待转存任务 |
| GET | `/api/pan/records` | 转存记录 |
| POST | `/api/pan/save` | 转存单个分享链接 |
| POST | `/api/pan/transfer` | 批量转存待处理任务 |
| POST | `/api/pan/mkdir` | 创建目录 |
| DELETE | `/api/pan/files` | 删除文件/目录 |
| GET | `/api/pan/download-url` | 换取临时直链（STRM / 投给 aria2） |
| POST | `/api/pan/{site_id}/test` | 连通性测试 |
| GET | `/api/pan/search?site_id=&keyword=` | **盘内搜索**（v1.7.0） |
| POST | `/api/pan/rename` | **改名**（v1.7.0） |
| POST | `/api/pan/move` | **移动 / 复制**（v1.7.0） |
| POST | `/api/pan/keep-alive` | **凭据保活巡检**（v1.7.0） |

网盘分享追更（v1.4.0）另有一组端点，详见 [`02-架构设计.md`](02-架构设计.md) §9.3：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / POST | `/api/v1/pan-subscribes` | 追更任务列表 / 新建 |
| PATCH / DELETE | `/api/v1/pan-subscribes/{id}` | 改 / 删 |
| POST | `/api/v1/pan-subscribes/{id}/check` | 立即巡检一个分享 |
| POST | `/api/v1/pan-subscribes/check-all` | 巡检全部 |

**优雅降级**：没有启用任何网盘时，这些端点返回
`{"success": false, "message": "没有可用的网盘存储，请先在站点管理中添加并启用"}`，
**不是 500**。某个盘不支持某个操作时返回明确提示而不是抛异常
——`BasePanStorage` 里 `mkdir` / `delete` / `download_url` / `rename` / `move` /
`copy` / `search` / `keep_alive` **全部有默认实现**，返回 False/空而**不抛
`NotImplementedError`**（ADR-28）。这样第三方或自建 Provider 不实现新方法也不会
把整个网盘页搞崩。

### 6.1 能力位矩阵（v1.7.0）

四种存储的能力差异很大，所以 `GET /api/pan` 会随总览下发每个盘的 `capabilities`，
**前端据此渲染按钮 —— 不支持的操作根本不显示**，而不是点了才报错（ADR-28）：

| 存储 | 浏览 | 转存 | 新建目录 | 删除 | 改名 | 移动 | 复制 | 盘内搜索 | 保活 |
|---|---|---|---|---|---|---|---|---|---|
| `quark` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `alist` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| `webdav` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | — |
| `local_dir` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | — |

几点实现说明：

- **WebDAV 不支持搜索**是协议层面的事实（没有搜索语义），
  谎报能力比不报更糟，所以 `supports_search = False`。
  改名/移动/复制统一走 `MOVE` / `COPY` 方法 + `Destination` 头 + `Overwrite: T`。
- **夸克盘内搜索**要用 `path_str` 拼出完整路径才能定位结果，否则只拿到文件名。
- **本地目录的 `rename` 拒绝含 `/` 或 `\` 的新名字**：
  带路径分隔符等于偷偷做移动，可能越出配置的 `base_dir`（安全边界）。
- 请求示例：

```bash
# 盘内搜索
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:6060/api/v1/pan/search?site_id=3&keyword=凡人修仙传"

# 改名
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"site_id":3,"path":"/影视/a.mkv","new_name":"凡人修仙传.S01E01.mkv"}' \
  http://127.0.0.1:6060/api/v1/pan/rename

# 移动（copy=true 则为复制）
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"site_id":3,"path":"/影视/a.mkv","target_dir":"/影视/国产剧","copy":false}' \
  http://127.0.0.1:6060/api/v1/pan/move
```

### 6.2 凭据保活（v1.7.0）

网盘 Cookie / token 会**静默过期**，原先的表现是半夜转存任务失败了才发现。
「网盘凭据保活」定时任务（默认每 **6 小时**，
`PAN_KEEPALIVE_INTERVAL_MINUTES` 可在设置页在线改）逐个存储调一次轻量接口：

- 多数网盘会因此**滑动续期**，延长可用时间；
- 真失效时**立刻告警**，而不是等到要转存时才暴露；
- 也可在网盘页点「凭据保活巡检」或调 `POST /api/pan/keep-alive` 手动触发。

> ⚠️ 这是「保活 + 告警」，**不是「永不掉线」**。
> 刻意**不做自动重新登录**：各网盘登录流程差异极大且多带验证码/短信验证，
> 自动化不可靠；能续期的续期，不能的明确告警让人来处理（ADR-33）。

## 7. 前端「网盘管理」页

- **容量卡**（`quotaCard()`）：每个盘一张卡，进度条 + 已用/总量，
  总量未知时百分比显示 0（很多网盘不给总量）。
- **面包屑**（`breadcrumb()`）：点击任意层级跳转，基于接口返回的 `parent`。
- **文件表**：目录可点进，文件可「直链」「删除」，
  v1.7.0 起还有「改名」「移动」，**按该盘的能力位决定是否渲染**。
- **盘内搜索框**（v1.7.0）：直接在网盘里按关键词找文件，
  不支持搜索的盘（如 WebDAV）不显示此框。
- **「凭据保活巡检」按钮**（v1.7.0）：手动跑一次保活，立刻看到每个盘的登录态。
- **待转存队列**：一键全部转存 / 单条转存。
- **转存记录表**：成功失败一目了然。
- **「转存分享链接」弹窗**：手动贴一个分享链接 + 提取码 + 目标盘，立即转存。

> v1.5.0 起：网盘转存类写操作需要 **operator** 及以上角色，
> 网盘**存储站点的配置**需要 **admin**（见 [02 §4.1](02-架构设计.md)）。
> 另外「站点健康」页也会巡检网盘存储站点的连通性。

另有两个 v1.4.0 新页面：

- **「分享追更」页**：4 张统计卡 + 巡检节奏卡（可直接改 `cineflow.pan_subscribe`
  周期或立即跑）+ 任务表 + 10 字段新建弹窗（分享链接 / 提取码 / 目标盘 /
  目标目录 / 包含 / 排除 / 正则 / 重命名规则 / 星期 / 到期时间）。
- **「STRM 同步」页**：4 张统计卡 + 链接模式说明卡 + 记录表
  + 同步弹窗 + 「测直链」「复制播放地址」。

## 8. 排障速查

| 现象 | 原因与处理 |
|---|---|
| 总览是空的 | 没有 `kind=panstorage` 的站点被**启用**（示例站点默认禁用） |
| 夸克全部失败 | Cookie 过期，重新复制浏览器完整 Cookie |
| AList 报 401 | 用户名密码错，或 `api_key` 填的不是 AList 令牌 |
| 转存「成功」但盘里没东西 | AList 是异步离线下载，去 AList 任务列表看进度 |
| 本地目录报「目录不存在」 | `base_dir` 路径写错，或容器内没挂载该路径 |
| 待转存一直不减少 | 看转存记录的 `message`；确认 `pan_transfer` 任务已启用 |
| 入库找不到转存下来的文件 | 网盘挂载路径与 `CF_LIBRARY_DIR` 不一致，见 [`07-运维手册.md`](07-运维手册.md) |
| 某个盘没有「改名」「移动」按钮 | **预期行为**：该 Provider 的能力位为 False（如 WebDAV 无盘内搜索）。按钮由后端 `capabilities` 驱动 |
| 改名报「名称不能包含路径分隔符」 | 本地目录的安全限制：带 `/` 或 `\` 等于偷偷移动、可能越出 `base_dir`。要移动请用「移动」 |
| 保活巡检显示某盘失败 | 凭据已彻底失效，保活救不回来。重新复制 Cookie / 重填账号密码。保活只能续期与告警，不会自动重新登录 |
