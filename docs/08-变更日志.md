### 🆕 新增

**可编辑运行期配置（M11）**
- `app/services/config_store.py`：`EDITABLE` 白名单（**51 项**）、`coerce()`
  类型/范围/枚举/cron 校验、`update()` / `reset()` / `describe()`。
- **先全部校验再落库**：一项非法整体拒绝，不留「改了 5 项、第 3 项报错」的半吊子状态。
- `apply_overrides()` 在启动时把表里的覆盖值回填进 `settings` 单例
  （`object.__setattr__`），所有既有 `settings.X` 读取点**零改动即热生效**。
- cron 校验复用 `scheduler.validate_cron()`，避免「设置页放过、调度器起不来」的两份规则漂移。
- `PUT /system/settings` + `POST /system/settings/reset`；
  `GET /system/settings` 每项补 `editable` / `type` / `choices` / `min` / `max` /
  `overridden` / `reschedule` / `hint` 元信息。
- 设置页整段重写为**可编辑表单**：按类型渲染控件、只提交改过的项、
  改过的标「已覆盖」、支持单项与全部恢复默认；不可热改项标「需重启」。

**多用户与三档权限（M12）**
- `UserRole` 三档枚举（`admin` / `operator` / `viewer`，带可比较的 `rank`）；
  `users` 表新增 `role` / `note`；`is_superuser` 改由 role 推导，保持永远一致。
- `app/api/deps.py` 新增 `role_of()` / `require_role()` / `OperatorUser` / `AdminUser`；
  **全部写端点按「配置类 → admin、运营类 → operator」重新挂依赖**。
- 鉴权读**数据库角色**而不是 JWT 里的副本：改完角色立即生效，不用等旧令牌过期。
- 两条自我保护：**不能删除/停用自己**、**最后一个启用中的管理员不能被降级或停用**。
- `/api/v1/users` CRUD（仅 admin）+ 前端「用户权限」页；
  侧栏显示当前身份，按角色隐藏没权限的入口（`visiblePages()` / `canDo()`）。
- 登录响应与 `/auth/me` 返回 `role` / `role_label` / `rank`。

**站点健康巡检（M13）**
- 新增表 `site_health` + `app/services/site_health.py`。
- 对搜索类站点**真搜一次**（而不是只探首页）：三档判定
  `ok` / `degraded`（能连通但 0 结果或极慢）/ `down`。
  **0 结果算降级**——Cookie 过期时首页照样能开，只有搜索结果会归零，
  这才是最难发现的故障。
- 连续失败达 `CF_SITE_HEALTH_FAIL_THRESHOLD`（3）才告警，且**只在状态翻转时通知**；
  用户手点探测时不发通知。
- 每站保留最近 50 条历史；可选连续失败**自动停用站点**（默认关闭）。
- `/api/v1/site-health` 概览/历史/单站探测/批量探测 + 前端「站点健康」页
  + `cineflow.site_health` 定时任务（默认 180 分钟）。

**下载器负载均衡与失败换源（M14）**
- 三种策略（`CF_DOWNLOADER_STRATEGY`）：`priority`（默认，与旧行为一致）/
  `least_tasks`（投给当前任务最少的）/ `round_robin`（轮询）。
- 结合健康数据把不健康的下载器**排到最后但不剔除**（健康数据可能过期，
  剔除会导致「明明能用却不投递」）。
- `downloader_candidates()` + BT 投递失败自动换下一个下载器
  （`CF_DOWNLOADER_FAILOVER`，默认开；关掉则行为与 v1.4.0 完全一致）。

**榜单自动订阅（M15）**
- 新增表 `ranking_rules` + `app/services/ranking.py`；4 个来源：
  TMDB 本周趋势 / TMDB 热门 / TMDB 高分 / **本地资源热度榜（无需 TMDB Key）**。
- 筛选条件：媒体类型、取前 N、最低评分、最低票数、最早年份、标题包含/排除。
- **单次上限** `CF_RANKING_MAX_PER_RUN`（默认 5）：否则一次能刷进上百个订阅。
- 记录 `handled_ids`（截断 500 条）：**用户手动删掉的订阅不会被下次巡检加回来**。
- 支持 `dry_run` 试算；`/api/v1/ranking-rules` CRUD + preview + run + run-all
  + 前端「榜单订阅」页 + `cineflow.ranking` 定时任务（默认 720 分钟）。
- `app/providers/metadata/tmdb.py` 新增 `ranking(source, media_type, limit)`。

**自定义过滤规则组（M16）**
- `app/core/rules.py`（**纯函数、无 IO**）：`RuleLevel` / `RuleGroup` /
  `level_matches` / `match_level` / `annotate` / `describe`。
- 规则组是**有序分层**：命中靠前层的资源整体优于靠后层，
  层内仍用既有 `score_resource` 排序（排序键 `(rule_level, -score)`）。
  这样才能表达「宁可 1080p 中字，也不要没字幕的 4K」——全局评分做不到。
- 每层条件全部**可留空 = 不限制**（分辨率/质量/特效/编码/包含/排除/做种/体积区间）。
- 新增表 `filter_rule_groups` + `app/services/rule_groups.py`：CRUD、
  默认组唯一性维护、`load_group()` 收敛 fallback（停用/不存在都退默认组）、`preview()` 试算。
- `subscribes` 新增 `rule_group_id`，可给单个订阅绑定规则组；
  搜索侧 `filter_and_rank(resources, rule, group)` 接入。
- 内置 4 个模板（画质优先 / 均衡 1080p 中字 / 省空间 / 动漫简繁内封），
  **全部 `is_default=False`**：规则组会改排序，升级后不能悄悄换掉用户熟悉的顺序。
- `/api/v1/rule-groups` CRUD + `{id}/preview` + 前端「过滤规则组」页。

### 🐛 修复

1. **非法 cron 会被静默存下来**：`normalize_schedule()` 原先只在
   `trigger == "cron"` 时校验 cron 表达式。于是一个 `interval` 任务可以存进
   `"这不是 cron"`，等用户哪天把 trigger 切成 cron 才起不来，
   那时他早忘了自己填过什么。改为**只要提交了 cron 字段就校验**
   （由本轮新增的冒烟用例发现，已补回归测试）。
2. 站点健康裁剪历史记录时**必须先 `session.flush()`**，否则本次刚写入的记录
   不参与计数，会永远多留一条。
3. `role_of()` 对历史脏值（非法/缺失 role）按 `is_superuser` 兜底，
   保证鉴权永远有确定结果——既不放行也不 500。

### ⚠️ 破坏性变更

无需人工迁移，但有两点行为变化需要注意：

1. ⚠️ **老库用户角色**：`users` 表补 `role` 列默认 `'admin'`
   （保证原来唯一的管理员不会被锁在系统外），启动时 `sync_user_roles()`
   再按 `is_superuser` 对齐一次——**原本 `is_superuser=false` 的账号会被置为
   `operator`**（而不是 viewer，避免突然失去已有的操作能力）。
   多用户老库升级后**请到「用户权限」页复核一遍角色**。
2. 全部写端点现在有角色要求。此前如果有脚本用非管理员账号的 JWT 调写接口，
   会开始收到 403；`X-API-Token` 走管理员身份，行为不变。

老库首次启动会自动补列，但**升级前仍建议照
[`07-运维手册.md`](07-运维手册.md) 备份 `data/cineflow.db`**。

  （实测老库补入 5 条）。示例站点 8 → **11** 条，全部默认禁用。

### 🐛 修复

1. `LocalDirStorage.base_dir` 未配置时返回 `Path("")`（等价于 `Path(".")`），
   会把**进程当前目录**当成网盘根目录。改为返回 `None` 并给出明确提示，
   同时支持 `file:///` 前缀写法。
2. 指令解析的 `_SEASON_RE` / `_EPISODE_RE` 用了 `\bS(\d{1,2})\b`，
   导致 `S01E09` 匹配不到季号。改为 `(?<![A-Za-z0-9])S(\d{1,2})(?!\d)`。
3. 指令解析里 `cleaned.replace(":", " ", 1)` 会把 `magnet:?xt=` 和 `https://`
   拆坏，导致「下载 magnet:…」失败。改为只替换紧跟指令词的第一个冒号。
4. `quark` / `alist` 的凭据改用 `self.option()` 读取，兼容填在 `options` 里的情况。

### ⚠️ 破坏性变更

**ChatOps Webhook 未配置验签密钥时，从放行改为默认拒绝（401）。**

原因：该端点不走 JWT 鉴权（平台无法携带），却能触发下载与删除网盘文件。
「忘配密钥 = 敞开大门」不可接受。详见 [`04-决策记录.md`](04-决策记录.md) ADR-04。

**升级动作**：给每个启用的平台补齐密钥；纯内网且明白风险者，
可在该平台配置里把 `allow_unverified` 填 `1` 恢复旧行为（会打 WARNING 日志）。
