## v1.4.0 · 2026-08-29 · 刮削 + WebDAV + STRM + 分享追更 + 洗版

> 本轮先用 `scripts/research_refs.py` 抓取同类开源项目（MoviePilot / quark-auto-save /
> SmartStrm / MediaWarp / TgtoDrive 等）的能力清单做差集，结论写进
> [`09-竞品对标与差距分析.md`](09-竞品对标与差距分析.md)，再据此排 M5~M10。

### 🆕 新增

**NFO 刮削与分类归档（M5 / M10）**
- `app/core/nfo.py`：纯渲染层（无 IO，可离线单测），产出 `movie` / `tvshow` /
  `season` / `episodedetails` 四种根节点，图片命名遵循媒体服务器惯例
  （`poster.jpg` / `fanart.jpg` / `seasonNN-poster.jpg`）。
- `app/services/scraper.py`：入库即刮 + 媒体库批量补刮；TMDB 不可用时
  **降级写最小 NFO** 并标记 `degraded`；默认**不覆盖**已有 NFO。
- `app/providers/metadata/tmdb.py` 增加 credits（演职员）获取。
- `POST /library/scrape` + 媒体库页「补刮 NFO」按钮 + `cineflow.scrape` 定时任务
  （默认 `30 4 * * *`，单次上限 `CF_SCRAPE_BATCH=200` 防打满 TMDB 限速）。
- `app/core/categories.py`：六类判定（电影/电视剧/动漫/纪录片/综艺/儿童），
  TMDB genre 优先、关键词兜底，**判不出返回 `None` 不归档**；
  `organizer` 据此建二级目录，默认关闭（`CF_CATEGORY_ENABLED=false`）。

**WebDAV 网盘存储（M6）**
- 新增 `webdav` 存储 Provider：`PROPFIND` 列目录、`MKCOL` 建目录、
  `PUT`/`DELETE` 读写、`quota-available-bytes` 查容量、路径 percent 编码。
- 一份实现覆盖 Nextcloud / 坚果云 / 群晖 Synology Drive / TeraCLOUD / AList DAV。
- 明确 `supports_save = False`（协议无「转存别人分享」语义），不假装成功。
- 提供 `auth_header()` 供 STRM 302 播放复用。

**STRM 同步 + 302 播放（M7）**
- 新增表 `strm_records` + `app/services/strm_sync.py`：把网盘目录递归映射成
  本地 `.strm`，Emby/Jellyfin 扫到即当成一集。
- 两种链接模式：`proxy`（**默认**，写 `/api/v1/strm/play/{id}`，链接永不过期）
  与 `direct`（写网盘临时直链，NAS 零参与但会过期）。
- `GET /api/v1/strm/play/{id}`：**匿名** 302 跳转（播放器带不了 JWT），
  只跳转不代理流量。
- 失效清理（`CF_STRM_CLEAN_INVALID`）避免媒体库里留下点开就报错的「幽灵剧集」；
  随行文件（字幕/NFO/图片）本地化（`CF_STRM_SYNC_METADATA`）。
- 新增「STRM 同步」页 + `cineflow.strm_sync` 定时任务（默认关闭）。

**网盘分享追更（M8）**
- 新增表 `pan_subscribes` + `app/services/pan_subscribe.py`：盯住一个分享链接
  持续追新，按文件名**增量**转存，不重复搬同一集。
- 包含/排除关键词 + 正则过滤；**用户写错正则按没填处理**，不搞崩巡检。
- 重命名规则（`第08集.mp4` → `剧名 - S01E08.mp4`）；限定星期几与到期时间控制节奏。
- 连续失败到 `CF_PAN_SUBSCRIBE_MAX_FAILURES`（5）标记 `invalid` 停手，死链不无限重试。
- 夸克实现 `list_share` / `save_share_files`；基类给出降级默认，
  不支持列举的网盘用哨兵 `__whole_share__` 防止反复整体转存。
- `/api/v1/pan-subscribes` CRUD + `{id}/check` + `/check-all`，
  新增「分享追更」页 + `cineflow.pan_subscribe` 定时任务（默认 60 分钟）。

**洗版（M9）**
- `app/services/upgrade.py`：发现明显更优版本时替换已入库文件。
- 三重防横跳：仅 `best_version=True` 订阅 + 评分差 ≥ `CF_UPGRADE_SCORE_DELTA`（15）
  + 每文件 ≤ `CF_UPGRADE_MAX_TIMES`（2）次。
- **先入库后删旧**（`library.replace_library_file`），中途失败不留空洞。
- `POST /subscribes/{id}/upgrade`、`POST /subscribes/upgrade-all`，
  订阅页「洗版试算」只报告不执行；`cineflow.upgrade` 定时任务。
- ⚠️ **默认关闭**（`CF_UPGRADE_ENABLED=false`），因为它会删除已入库文件。

**调研脚本**
- `scripts/research_refs.py`：抓取同类项目 README/topics，提取特性关键词与
  本项目已实现能力做差集，无网络时输出内置快照，不阻塞。

### 🐛 修复

1. **老库升级 500**：`Base.metadata.create_all()` 只建新表、**不给已有表加列**，
   因此带旧 `library_files` 的库升级到 v1.4.0 后 `/system/dashboard`、
   `/library/files` 与两个插件会 500（已实测复现）。
   修复方式为启动时执行 `migrate_columns()` 幂等补列（ADR-17），
   并补了老库升级的接口用例。
2. 分享追更里用户填的非法正则会让整轮巡检抛 `re.error` 中断，
   改为 `_compile()` 捕获并按「没填」处理。
3. 不支持 `list_share` 的网盘在分享追更里每轮都会整体转存一次，
   改用 `__whole_share__` 哨兵记录已整体转存过。

### ⚠️ 破坏性变更

无。新增配置项均有默认值；两个会改动磁盘布局/删除文件的能力
（分类归档、洗版）**默认关闭**，需用户显式开启。
老库首次启动会自动补列，无需人工迁移，但**升级前建议照
[`07-运维手册.md`](07-运维手册.md) 备份 `data/cineflow.db`**。

## v1.3.0 · 2026-08-28 · 网盘管理 + ChatOps + 文档体系

### 🆕 新增

**文档体系（M1）**
- 新建 `docs/`，9 篇文档：索引、项目现状、架构设计、升级路线图、
  决策记录（ADR 10 条）、ChatOps 手册、网盘管理手册、运维手册、本变更日志。
- `scripts/verify_docs.py` 增加文档校验：文件存在、篇幅下限、索引完整、
  路线图无占位、变更日志覆盖全版本。**文档过期会导致门禁失败。**

**网盘管理（M2）**
- 新增 Provider 类别 `panstorage`（存储器），与已有 `pan`（盘搜/搜索器）明确分工。
- `BasePanStorage` 抽象 + 3 个实现：`alist`（推荐网关）、`quark`（直连样板，
  完整四步转存）、`local_dir`（本地/挂载目录，零配置试用，含路径越界防护）。
- `app/services/pan_storage.py`：容量、目录浏览、转存、批量转存、建目录、
  删除、直链、连通性测试；同家网盘优先的转存目标选择策略。
- 10 个网盘 API（`/api/pan/*`），含转存记录 `GET /pan/records`。
- 新增数据表 `pan_saves`（转存记录）。
- 前端「网盘管理」页：容量卡 + 面包屑目录浏览 + 文件表（直链/删除）
  + 待转存队列（一键全部转存/单条）+ 转存记录 + 手动转存分享链接弹窗。
- 打通 `download.add_download()`：网盘资源**自动转存**而非仅登记
  （`CF_PAN_AUTO_SAVE`，默认开）。
- 新增内置定时任务 `cineflow.pan_transfer`（默认 20 分钟），
  批量重试待转存队列。内置任务 4 → **5** 个。

**ChatOps 机器人（M3）**
- 入站 Webhook 框架：逐平台验签、防重放、10 分钟幂等去重、用户白名单。
- 三平台适配器：飞书（v1/v2 token + URL 验证挑战 + AES-CBC 加密推送解密）、
  钉钉（HMAC-SHA256 时间戳签名 + 时钟漂移检查 + sessionWebhook 回复）、
  Telegram（`X-Telegram-Bot-Api-Secret-Token` 校验）。
- 指令解析器：**42 个别名 → 8 个规范指令**
  （搜索/下载/订阅/订阅列表/状态/转存/热榜/帮助）；
  支持中文季集号、`S01E09`、冒号写法、`@提及`剥离、纯数字兜底、片名直搜兜底。
- 会话上下文：`搜索` 后回 `下载 2` 即可，按 `平台+会话+用户` 隔离，
  默认 900 秒过期（`CF_CHATOPS_SESSION_TTL`）。
- 8 个 ChatOps API；适配器自带 `config_fields` 声明，前端表单**自动渲染**，
  避免前后端两份字段硬编码。
- 前端「机器人」页：全局设置 + 三平台卡（可一键复制回调地址）
  + 指令试跑（执行/只解析）+ 指令别名表 + 审计日志表。
- 指令审计写入 `audit_logs`，可按渠道筛选。

**可用性收口（M4）**
- `GET /system/settings`：9 个分组、47 个配置项只读展示，
  敏感项（`SECRET`/`TOKEN`/`PASSWORD`/`API_KEY`）脱敏为 `******（已设置）`。
- 前端「设置」页：配置分组表 + 改密 + 通知测试 + 「如何修改配置」说明。
- 导航新增分组归属：网盘管理 → 入库；机器人、设置 → 系统。

### 🔧 变更

- `create_default_sites()` 由「表非空即跳过」改为**按 name 逐条补齐**，
  老库升级也能看到新增示例站点，且**不覆盖**用户已改过的配置
  （实测老库补入 5 条）。示例站点 8 → **11** 条，全部默认禁用。
- `app/core/version.py` → `1.3.0`。
- 新增 9 个 `CF_` 配置项（`CF_PAN_*` 3 个、`CF_CHATOPS_*` 5 个及相关）。

### 🐛 修复

1. `LocalDirStorage.base_dir` 未配置时返回 `Path("")`（等价于 `Path(".")`），
   会把**进程当前目录**当成网盘根目录。改为返回 `None` 并给出明确提示，
   同时支持 `file:///` 前缀写法。
2. 指令解析的 `_SEASON_RE` / `_EPISODE_RE` 用了 `\bS(\d{1,2})\b`，
   导致 `S01E09` 匹配不到季号。改为 `(?<![A-Za-z0-9])S(\d{1,2})(?!\d)`。
3. 指令解析里 `cleaned.replace(":", " ", 1)` 会把 `magnet:?xt=` 和 `https://`
   拆坏，导致「下载 magnet:…」失败。改为只替换紧跟指令词的第一个冒号。
4. `quark` / `alist` 的凭据改用 `self.option()` 读取，兼容填在 `options` 里的情况。

### ⚠️ 破坏性变更

**ChatOps Webhook 未配置验签密钥时，从放行改为默认拒绝（401）。**

原因：该端点不走 JWT 鉴权（平台无法携带），却能触发下载与删除网盘文件。
「忘配密钥 = 敞开大门」不可接受。详见 [`04-决策记录.md`](04-决策记录.md) ADR-04。

**升级动作**：给每个启用的平台补齐密钥；纯内网且明白风险者，
可在该平台配置里把 `allow_unverified` 填 `1` 恢复旧行为（会打 WARNING 日志）。

## v1.0.0 · 2026-08-28 · 首个可用版本

- 🆕 从零实现 NAS 影视自动化平台：聚合搜索 → 自动追新 → 择优下载 →
  规范命名入库 → 通知媒体服务器。

- 🆕 订阅巡检、下载监控、整理入库（硬链接优先）、STRM 生成、插件机制。

  代码与数据模型完全独立编写。
