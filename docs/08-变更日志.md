## v1.3.0 · 2026-08-28 · 网盘管理 + ChatOps + 文档体系

### 🆕 新增

**文档体系（M1）**
- 新建 `docs/`，9 篇文档：索引、项目现状、架构设计、升级路线图、
  决策记录（ADR 10 条）、ChatOps 手册、网盘管理手册、运维手册、本变更日志。
- `scripts/verify_docs.py` 增加文档校验：文件存在、篇幅下限、索引完整、
  路线图无占位、变更日志覆盖全版本。**文档过期会导致门禁失败。**

**网盘管理（M2）**
- 新增 Provider 类别 `panstorage`（存储器），与已有 `pan`（盘搜/搜索器）明确分工。
- `BasePanStorage` 抽象 + 3 个实现：`alist`（推荐网关）、`quark`（直连样板，
  完整四步转存）、`local_dir`（本地/挂载目录，零配置试用，含路径越界防护）。
- `app/services/pan_storage.py`：容量、目录浏览、转存、批量转存、建目录、
  删除、直链、连通性测试；同家网盘优先的转存目标选择策略。
- 10 个网盘 API（`/api/pan/*`），含转存记录 `GET /pan/records`。
- 新增数据表 `pan_saves`（转存记录）。
- 前端「网盘管理」页：容量卡 + 面包屑目录浏览 + 文件表（直链/删除）
  + 待转存队列（一键全部转存/单条）+ 转存记录 + 手动转存分享链接弹窗。
- 打通 `download.add_download()`：网盘资源**自动转存**而非仅登记
  （`CF_PAN_AUTO_SAVE`，默认开）。
- 新增内置定时任务 `cineflow.pan_transfer`（默认 20 分钟），
  批量重试待转存队列。内置任务 4 → **5** 个。

**ChatOps 机器人（M3）**
- 入站 Webhook 框架：逐平台验签、防重放、10 分钟幂等去重、用户白名单。
- 三平台适配器：飞书（v1/v2 token + URL 验证挑战 + AES-CBC 加密推送解密）、
  钉钉（HMAC-SHA256 时间戳签名 + 时钟漂移检查 + sessionWebhook 回复）、
  Telegram（`X-Telegram-Bot-Api-Secret-Token` 校验）。
- 指令解析器：**42 个别名 → 8 个规范指令**
  （搜索/下载/订阅/订阅列表/状态/转存/热榜/帮助）；
  支持中文季集号、`S01E09`、冒号写法、`@提及`剥离、纯数字兜底、片名直搜兜底。
- 会话上下文：`搜索` 后回 `下载 2` 即可，按 `平台+会话+用户` 隔离，
  默认 900 秒过期（`CF_CHATOPS_SESSION_TTL`）。
- 8 个 ChatOps API；适配器自带 `config_fields` 声明，前端表单**自动渲染**，
  避免前后端两份字段硬编码。
- 前端「机器人」页：全局设置 + 三平台卡（可一键复制回调地址）
  + 指令试跑（执行/只解析）+ 指令别名表 + 审计日志表。
- 指令审计写入 `audit_logs`，可按渠道筛选。

**可用性收口（M4）**
- `GET /system/settings`：9 个分组、47 个配置项只读展示，
  敏感项（`SECRET`/`TOKEN`/`PASSWORD`/`API_KEY`）脱敏为 `******（已设置）`。
- 前端「设置」页：配置分组表 + 改密 + 通知测试 + 「如何修改配置」说明。
- 导航新增分组归属：网盘管理 → 入库；机器人、设置 → 系统。

### 🔧 变更

- `create_default_sites()` 由「表非空即跳过」改为**按 name 逐条补齐**，
  老库升级也能看到新增示例站点，且**不覆盖**用户已改过的配置
  （实测老库补入 5 条）。示例站点 8 → **11** 条，全部默认禁用。
- `app/core/version.py` → `1.3.0`。
- 新增 9 个 `CF_` 配置项（`CF_PAN_*` 3 个、`CF_CHATOPS_*` 5 个及相关）。

### 🐛 修复

1. `LocalDirStorage.base_dir` 未配置时返回 `Path("")`（等价于 `Path(".")`），
   会把**进程当前目录**当成网盘根目录。改为返回 `None` 并给出明确提示，
   同时支持 `file:///` 前缀写法。
2. 指令解析的 `_SEASON_RE` / `_EPISODE_RE` 用了 `\bS(\d{1,2})\b`，
   导致 `S01E09` 匹配不到季号。改为 `(?<![A-Za-z0-9])S(\d{1,2})(?!\d)`。
3. 指令解析里 `cleaned.replace(":", " ", 1)` 会把 `magnet:?xt=` 和 `https://`
   拆坏，导致「下载 magnet:…」失败。改为只替换紧跟指令词的第一个冒号。
4. `quark` / `alist` 的凭据改用 `self.option()` 读取，兼容填在 `options` 里的情况。

### ⚠️ 破坏性变更

**ChatOps Webhook 未配置验签密钥时，从放行改为默认拒绝（401）。**

原因：该端点不走 JWT 鉴权（平台无法携带），却能触发下载与删除网盘文件。
「忘配密钥 = 敞开大门」不可接受。详见 [`04-决策记录.md`](04-决策记录.md) ADR-04。

**升级动作**：给每个启用的平台补齐密钥；纯内网且明白风险者，
可在该平台配置里把 `allow_unverified` 填 `1` 恢复旧行为（会打 WARNING 日志）。

## v1.0.0 · 2026-08-28 · 首个可用版本

- 🆕 从零实现 NAS 影视自动化平台：聚合搜索 → 自动追新 → 择优下载 →
  规范命名入库 → 通知媒体服务器。
- 🆕 多级关键词并发搜索、BT + 网盘双通道、按 infohash 跨站去重。
- 🆕 硬过滤（枪版/无关剧/做种不足）+ 加权打分（4K>1080p、中字 +30、季包 +25）。
- 🆕 Provider 体系：indexer / pan / downloader / mediaserver / notifier / metadata。
- 🆕 订阅巡检、下载监控、整理入库（硬链接优先）、STRM 生成、插件机制。
- 🆕 零依赖原生前端（无 CDN、无构建，见 ADR-08）。
- 🆕 Docker Compose 一键部署 + 可选配套服务（Jackett / qBittorrent / PanSou / Emby）。
- 📝 设计上参考 [MoviePilot](https://github.com/jxxghp/MoviePilot) 的订阅/插件体系与
  [T3FAP](https://github.com/qq85423296/T3FAP) 的网盘资源思路，
  代码与数据模型完全独立编写。
