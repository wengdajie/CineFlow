# 浏览器登录与 Cookie 自动回填

v1.29.2 修复夸克登录后不回填的问题。助手获取到登录 Cookie 后立即返回控制台并回填，再由 CineFlow 校验；有效时保存账号并关闭本次助手打开的登录页。校验失败会保留回填内容并显示原因，不保存失效凭据。

## 首次配置（Chrome / Edge 桌面版）

1. 在“网盘管理 → 登录网盘 → 夸克网盘”点击“浏览器登录”，或打开“导入 Cookie”。
2. 点击“下载登录助手”，解压 `cineflow-login-helper.zip` 到固定目录。
3. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。开启“开发者模式”，选择“加载已解压的扩展”，选中含 `manifest.json` 的目录。
4. 点击浏览器工具栏中的“CineFlow 网盘登录助手”。填写控制台的完整地址，例如 `http://192.168.1.10:6060`，点击“保存并连接”，允许该站点权限。弹窗的“首次配置登录助手”中也会显示当前地址，可直接复制。
5. 返回控制台，点击“跳转登录并自动获取”，在夸克官网完成登录即可。

**从 v1.29.1 升级必须同时更新助手至 1.1.0**：重新下载 ZIP，解压覆盖原扩展目录，在扩展管理页点击“重新加载”，最后刷新 CineFlow 页面。更新服务或 Docker 镜像不会自动更新本机已安装的扩展。控制台会检测旧版本并提示更新。

扩展只需首次安装和连接；后续直接使用登录按钮。CineFlow 地址或端口变化后，在扩展里重新连接。更新扩展时覆盖原解压目录并在扩展管理页点“重新加载”，保留原连接设置。

## 使用行为

- “浏览器登录”会打开本次流程专用的夸克官网标签页。浏览器已经登录时，可直接尝试现有登录态。
- 检测到 `__puus` 或 `__pus` 即回填并返回原 CineFlow 标签页，不再强制两者同时存在。是否有效仍由服务端校验，只有校验通过才保存。原有手动粘贴与“校验并保存”仍可使用。
- 校验失败时，控制台显示“Cookie 已回填，但未保存”和具体原因，官网标签页保持打开；Cookie 更新后会再次校验。
- 如果已登录但仍未返回，在夸克页面点击浏览器工具栏的登录助手，再点“重新检测并回填”；控制台弹窗也提供同名按钮。主动检测允许同一 Cookie 重新校验，以恢复临时网络错误；30 秒未收到校验回执时也可主动恢复。
- 未检测到登录字段或无法读取站点 Cookie 时，会在控制台和助手弹窗显示原因及后续操作，不输出 Cookie 值。
- 关闭控制台登录弹窗或关闭助手打开的官网标签页，会取消等待。等待超过 10 分钟自动结束。浏览器重启后需重新开始。
- 支持 NAS、Docker 和源码部署。扩展运行在访问控制台的电脑浏览器里，NAS/Docker 不需要安装浏览器、桌面或远程桌面服务。
- 当前自动获取只支持夸克，要求 Chrome/Edge 120 或更新版本。手机浏览器、Safari 等可继续手动导入；115 和百度保留原扫码入口。

## 为什么需要扩展

普通网页无法直接读取另一个站点的 Cookie，尤其是 HttpOnly Cookie。助手通过浏览器提供的 [cookies API](https://developer.chrome.com/docs/extensions/reference/api/cookies) 获取对应夸克接口的 Cookie，再通过受限的 [扩展消息通道](https://developer.chrome.com/docs/extensions/develop/concepts/messaging) 回传。

- 只有用户发起登录后才读取夸克 Cookie；没有后台定时收集功能。
- 回传前验证配置的控制台源地址、端口、标签页、顶层窗口和本次请求标识。页面导航到其他源地址后不回传。
- Cookie 不写入扩展存储、不放进 URL、不记录日志，也不读取 CineFlow 的登录令牌。扩展本地存储只保存连接地址；临时存储只保存会话元数据和 Cookie 摘要。
- 凭据通过控制台已有的 `POST /api/v1/pan/login/cookie` 接口校验并写入对应站点。该接口继续执行原有权限检查，响应不返回 Cookie。
- 登录成功或取消时，只关闭助手为本次流程创建、且仍位于夸克官网的标签页，不操作用户原有标签页。

## 接口与打包

- `GET /api/v1/pan/login/providers` 对夸克返回新增能力 `browser: true`，原服务端扫码能力仍为 `qrcode: false`。浏览器中官网自己的登录方式不受此标记影响。
- `GET /api/v1/pan/login/browser-extension` 需要 CineFlow 登录，动态打包公开扩展源文件和说明。不读取服务器配置、数据库或用户浏览器目录。
- 扩展源文件位于 `web/assets/login-helper/`，随 Docker 镜像中的 Web 资源一起发布；控制台弹窗为 `web/assets/pages/pan_cookie_login.js`。

## 验证范围

- Python 3.10、3.12 各 1857 项本地回归通过。
- Node 验证 23 项桥接契约，包括源地址/端口/iframe/隐私窗口限制、请求标识与标签页/文档绑定、并发、单字段/host-only Cookie、读取失败提示、同 Cookie 主动重试、丢失回执恢复、助手弹窗来源校验、Cookie 变更重试、取消、刷新、导航、配置变更和超时。
- 真实 Chromium 扩展使用独立临时配置和模拟的官网页面，读取单个 host-only 合成 HttpOnly Cookie，验证失效凭据回填但不保存、控制台与助手弹窗主动重试、更新后自动保存并返回、旧助手升级提示、取消关闭专用标签页、390 像素宽页面不整体溢出，脚本错误为 0。
- 本轮没有登录真实夸克账号，也未读取用户个人浏览器配置。平台实际登录、网络和账号风控仍需用户在官网完成登录后确认。

本地验证证据位于 Git 忽略的 `.tmp/cookie-login/`，包括浏览器结果、截图和两套 Python 测试日志。容器冒烟流程同时检查扩展 ZIP 是否随镜像正确提供。
